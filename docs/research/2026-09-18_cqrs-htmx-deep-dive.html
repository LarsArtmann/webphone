02Summary — the bottom line

Are we using cqrs-htmx fully and superbly? Split verdict. For the three capabilities webphone touches — the embedded htmx.min.js handler, the embedded SSE extension handler, and the per-extension Broadcaster — usage is exemplary: version-current, following the library's own documented patterns (Hub() as the canonical fan-out accessor, embedded assets instead of CDN), and correctly extended consumer-side with a per-extension hub registry the library deliberately leaves open.

But the library is used as an asset server + event hub, not as the HTTP middleware toolkit the same import provides. Directly beside cqrs-htmx calls, webphone hand-rolls a weaker panic-recovery middleware (no stack trace, and it swallows http.ErrAbortHandler, which net/http convention requires re-raising), a weaker keyed rate limiter (no key-count cap under spoofed floods), ships no request logging at all, and serves a /healthz that always says ok without checking SQLite. All four have first-class equivalents in the already-imported package or its direct re-exports.

The bottom line Core usage: superb. Breadth: 3 of ~10 applicable capability groups. The Pareto fix is about one hour — delete recovery(), adopt four ready middlewares — moves the score to ~90 without touching a single line of the DOM contract the stack's E2E depends on.
Update 2026-09-18 — executed All four middlewares adopted, both duplications deleted, honest readiness live; all four gates green (full suite incl. DOM contract, vet/gofmt, buildflow, nix flake check). Re-score: 92 (rubric appendix 09).

03Current usage — what the project does today

✓
Embedded HTMX script — canonical cqrshtmx.HTMXScriptHandler() serves the version-pinned htmx.min.js at /htmx.min.js (internal/server/server.go:101). CSP-safe: no CDN, no HTMXCDNScriptTag temptation — matches the same-origin-only CSP invariant.
✓
Embedded SSE extension — canonical cqrshtmx.HTMXExtensionHandler("sse") serves the vendored sse.min.js (server.go:102) that powers sse-connect/sse-swap in the shell (internal/web/views/layout.templ:59).
✓
Per-extension SSE broadcaster — canonical + correctly extended cqrshtmx.NewBroadcaster() per extension, events pumped via hub.Hub().Subscribe()/Unsubscribe and pushed with Broadcast(sse.Event{Event, Data}) (internal/server/sse.go:75-104). This is exactly the pattern in the library's doc comment; the ExtensionHubs registry adds per-extension isolation (no cross-extension leakage) the library intentionally leaves to the consumer.
✓
Swap-safe fragment publishing The notifier renders templ fragments into the SSE Data field so sse-swap replaces exactly the live region (internal/server/notifier.go:63-70) — the library's intended "data IS the rendered HTML" transport.

The whole import surface is two files and four symbols (HTMXScriptHandler, HTMXExtensionHandler, NewBroadcaster/Broadcaster). The setup bundle and everything dispatch-coupled is deliberately not adopted — a documented architecture decision (AGENTS.md: this product's identity is the PBX extension, not an event-sourced user database). The go-cqrs-lite modules visible as indirect dependencies ride along unused, exactly as that decision implies.

04Capability assessment — findings by impact

Misused / Anti-pattern · High impact

Hand-rolled recovery() duplicates RecoveryMiddleware — and is weaker

internal/server/server.go:131-141 · wired at server.go:128

The library offers cqrshtmx.RecoveryMiddleware, which (a) re-panics http.ErrAbortHandler per net/http convention, (b) logs a full debug.Stack() with method/path and request/correlation IDs, and (c) writes the 500 through the classified error handler. Webphone's 11-line version swallows http.ErrAbortHandler (misclassifying connection aborts as server bugs and attempting a 500 write on an aborted stream) and logs no stack trace — a panic in production is debugged from a one-line "panic in handler" record.

Recommendation Delete recovery() and wrap with the library middleware. Behavior is a strict superset; no DOM or route changes.
Before — hand-rolled
After — library
func recovery(next http.Handler) http.Handler {
  return http.HandlerFunc(func(w, r) {
    defer func() {
      if rec := recover(); rec != nil {
        slog.Error("panic in handler",
          "path", r.URL.Path, "panic", rec)
        http.Error(w, "internal error", 500)
      }
    }()
    next.ServeHTTP(w, r)
  })
}
// server.go:128
return security(recovery(root))
// no recovery() function at all
return security(cqrshtmx.RecoveryMiddleware(root))
Missed Opportunity · High impact

No request logging anywhere — RequestLoggingSlog is one line

cmd/webphone/main.go (startup log only) · middleware chain at internal/server/server.go:110-128

For a communications product whose runbook greps logs, webphone emits no per-request records: no method/path/status/duration. The library ships cqrshtmx.RequestLoggingSlog(logger) (plus DefaultLogFormatter/JSONLogFormatter) exactly for this; the cqrs-htmx setup bundle composes it outermost by default. It logs the request line only — never bodies — so credentials in POST /api/session stay out of logs.

Recommendation Wrap the outermost handler; pass the process logger. 
return cqrshtmx.RequestLoggingSlog(slog.Default())(
  security(cqrshtmx.RecoveryMiddleware(root)),
)
Partially Used · Medium-high impact

83-line keyedLimiter reimplements KeyedRateLimiter (re-exported as cqrshtmx.RateLimiterMiddleware)

internal/server/ratelimit.go:1-83 (+ ratelimit_test.go) · used at server.go:61-62, 96, 108

The httputil limiter that cqrs-htmx re-exports is a strict superset: a MaxKeys cap with oldest-entry eviction bounds memory under a spoofed-source flood (webphone's 1-minute sweep admits unbounded unique keys within a sweep window), Retry-After is computed from the window instead of hardcoded "2", configuration is validated with classified errors, and KeyExtractorFromClientIP can resolve real client IPs behind the stack's TLS terminator — where webphone's own comment concedes every request shares the proxy socket, making its per-IP limit effectively global. (Header trust is a deployment decision: adopt KeyExtractorFromClientIP only if the stack sanitizes X-Forwarded-For; otherwise keep the RemoteAddr extractor.)

Recommendation Replace both limiter instances with the httputil middleware (identical family webphone already imports directly for CSRF/security headers; the cqrs-htmx re-export is the same object). Delete ratelimit.go, adapt its two tests.
Before — hand-rolled
After — library
loginLimiter: newKeyedLimiter(loginRate, loginBurst),
hookLimiter:  newKeyedLimiter(hookRate, hookBurst),
// + 83 lines of buckets, sweep, middleware
// + hardcoded Retry-After: 2
loginLimiter := &httputil.KeyedRateLimiterConfig{
  Limit: 30, Window: time.Minute, Burst: 5,
  KeyExtractor: httputil.KeyExtractorFromRemoteAddr(),
}.Middleware()
// MaxKeys-capped, computed Retry-After,
// config errors classified as Rejection
Partially Used · Medium impact

events handler reimplements Broadcaster.ServeSSE minus two features

internal/server/sse.go:88-123 (36 lines) vs sse_broadcaster.go:155-186 in the library

Broadcaster.ServeSSE performs the full lifecycle in one call: stream creation, a retry: reconnect hint (transport.DefaultRetryHintMillis), an initial connected event, the same 15 s heartbeat webphone hand-picks, and guaranteed unsubscribe/close. Correction (tag-verified 2026-09-18 against the consumed v4.9.0 bytes in the module cache): ServeSSE performs stream creation, the initial connected event, the 15 s heartbeat and guaranteed unsubscribe/close — but sends no retry: hint at this tag; transport.DefaultRetryHintMillis does not exist in v4.9.0 (master-only, if anywhere). Reconnect timing stays the browser default. Webphone's hand loop forgoes the retry: hint Nothing is lost by adopting: the only real deltas are the connected handshake frame (additive — the island's sse-swap listeners ignore unknown event names) and a heartbeat that now correctly rides the request context. The session gate and SetLang compose cleanly in front of it.

Recommendation Collapse the loop; keep the wrapper for auth + language capture. Done 2026-09-18 (commit aacae89); wire shape byte-verified by TestSSEStreamCarriesConnectedThenEvents. 
func (h *handlers) events(w http.ResponseWriter, r *http.Request) {
  sess, ok := session.From(r.Context())
  if !ok { http.Error(w, "sign in first", http.StatusUnauthorized); return }
  h.deps.Hubs.SetLang(sess.Extension, h.lang(r))
  h.deps.Hubs.serve(sess.Extension)(w, r) // Broadcaster.ServeSSE
}
Missed Opportunity · Medium impact

/healthz always says ok — ReadinessHandler + NamedCheck exist for this

internal/server/server.go:143-147

The constant "ok" response cannot detect a broken SQLite handle or an unwritable blob directory; the consuming stack gets no signal to stop routing to a wedged instance. The library's composable readiness surface is cqrshtmx.ReadinessHandler(NamedCheck{...}) — each named check returning an error turns the endpoint 503 with the failing check named.

Recommendation Keep the route, swap the handler; one ping check covers the real failure mode. 
open.Handle("GET /healthz", cqrshtmx.ReadinessHandler(
  cqrshtmx.NamedCheck{Name: "sqlite", Check: db.Ping},
))
Fully Leveraged · builds confidence

internal/server/server.go:101-102 · internal/server/sse.go:75-104 · internal/server/notifier.go:63-70

08Conclusion

Webphone's cqrs-htmx posture is narrow but deep where it counts: the imported core (embedded assets, broadcaster) is current, canonical, and extended in the library's intended seams. The adoption score of 62 reflects breadth, not quality — four cross-cutting middleware capabilities sit unadopted while weaker hand-rolled copies (recovery, rate limiting) or nothing at all (request logging, readiness) do the job beside them. Executing items 1–4 of the action plan — roughly an hour of middleware-seam changes with zero DOM-contract risk — raises the score to ~90 and deletes ~200 lines of duplication. The refusal record (dispatch layer, security presets, error envelopes) is sound and should stand.
