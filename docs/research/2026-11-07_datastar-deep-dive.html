00Summary

The premise is half right: webphone serves 9,844 lines of JS (custom + vendored), and none of it is a framework. But the shape of that code is the answer to the question. 3,560 lines across eight island modules are WebRTC/SIP orchestration — sip.js sessions, RTCPeerConnection, getUserMedia, AudioContext capture, device routing, hold/ring state machines — which Datastar's own vocabulary (data-ignore, web components) exists to fence OFF, not absorb. The shell's server-driven surface is already declarative: 164 pinned hx-* attributes with morph swaps over the same go-sse transport Datastar builds on. What remains are thin delegated affordances whose replacement would cost a third CSP lane and a second reactive idiom.

The bottom line Full client-side adoption is a NO. It reaffirms the 2026-11-04 transitive ruling (docs/review/libs/go-datastar.md) with the client-side evidence that ruling lacked, and it supersedes that ruling's refresh-trigger paragraph: the trigger does not fire. The audit ships one actionable finding: /health's 'unsafe-eval' grant is now avoidable — the embedded v1.0.3 engine ships a nonce + Trusted Types lane the dashboard library does not use yet (filed in TODO_LIST).

◆Current usage

Datastar is not absent from webphone — it is deliberately scoped to the one surface whose shape fits it. This is the baseline the adoption question starts from.

+
The health dashboard already rides it internal/app/dashboard.go:55 — dashboard.WithEmbeddedDatastarSDK(); the embedded engine (v1.0.3, 33,538 bytes) serves from /health/datastar.js. A live server-driven metrics page with zero custom JS is exactly Datastar's sweet spot.
+
The realtime fabric is shared /events rides go-sse — the same transport go-datastar builds its patches-as-values model on (SDK README: every patch is an sse.Event). Adopting the protocol later would reuse the existing hub, not replace it.
+
The tab surface is already declarative 164 hx-* attributes across the templ views (42 hx-swap, 36 hx-target, 22 hx-post, 16 hx-get, …) with morph:innerHTML swaps on five live surfaces — the same reactive-server pattern Datastar's element patches implement, already pinned by the DOM contract and the stack browser E2E.
+
The island's state machines are test-owned 46 node:test modules pin hold pending/queued transitions, ring queueing, dial-gate verdicts, transcription lifecycle, drafts guards — the honesty contract is executable, not aspirational.
+
CSP postures are test-fenced strict shell (TestServedPageSatisfiesStrictCSP, internal/server/server_test.go:516), nonce lane only on /login (login_page_test.go:18), eval lane only on /health (TestAppDashboardMountsHealthSubtree, internal/app/app_test.go:135).

Dependency shape: go-datastar v0.6.2 + go-datastar/static v0.6.1 + templ-components/datastar v1.27.0, all indirect, all consumed exclusively through the dashboard lane — webphone's own Go code imports none of them. The engine bundle carries a v1.0.3 header and boots one of two expression lanes: bare Function() (eval) or, when <html data-nonce> is present, a Trusted Types policy + nonced script injection — both verified in the bundle's bytes.

01Findings

Ordered by impact. F1–F3 carry the verdict; F4 is the one actionable miss; F5–F7 close the remaining pro-adoption arguments honestly.

Verdict core · Architecture

F1 · The island is exactly what Datastar fences off — 3,560 lines stay imperative under any posture

internal/web/assets/island/app/ · calls.js 1,847 · transcribe.js 535 · connection.js 469 · ice.js 201 · audio.js 142 · audioout.js 140 · mic.js 116 · pcsetup.js 96

This is the decisive fact. The island is sip.js session orchestration (INVITE/REFER/NOTIFY sipfrag, DTMF as application/dtmf-relay), RTCPeerConnection setup, getUserMedia device capture, AudioContext ASR routing with setSinkId tone routing, a watchdog around sip.js 0.21.2's known reconnect hang, and pending-state machines (hold pending/queued, ring queue). Upstream Datastar's own answer for code like this is to keep it imperative: data-ignore skips a subtree entirely (the reference frames it as the escape hatch for third-party libraries), and the framework's sanctioned bridge for imperative code is wrapping it in a web component — the data-star.dev homepage demo is itself an imperative star-field custom element driven by data-attr:*. "Full Datastar" therefore means hosting these 3,560 lines unchanged behind a fence: zero lines removed, one paradigm added.

Resolution Keep the island imperative. Its boundaries are already enforced: internal/arch/arch_test.go pins the acyclic module graph, and TestIslandModulesMatchImportClosure pins the entry surface.
Verdict core · One-idiom doctrine

F2 · The declarative surface already exists — it is HTMX, and it is load-bearing

internal/web/views/*.templ · 164 hx-* attribute instances · cqrs-htmx foundation (100/100, 2026-10-25 audit)

The tabs are not hand-rolled JS — they are server-rendered templ fragments swapped by htmx with hx-swap="morph:innerHTML" (idiomorph) on the thread list, transcript, fax list, contacts panel and voicemail re-fetch; focus, drafts and listeners survive swaps by design. Datastar's element patches implement the same server-morphs-DOM pattern — adopting them beside htmx buys a second morph idiom that can disagree with the first, and replacing htmx orphans the cqrs-htmx response vocabulary the whole server is shaped around. The 2026-11-04 ruling priced exactly this ("a second reactive idiom for zero product gain"); this audit adds the number that mattered: the would-be replacement surface is 164 pinned sites, not greenfield.

Verdict core · Security posture

F3 · Expressions are eval-shaped — the strict shell CSP is the wall, and the nonce lane is not free

datastar.js (go-datastar/static@v0.6.1) · 1 Function( occurrence in the bundle · pins: internal/server/server_test.go:516, internal/server/login_page_test.go:18

Every data-on:* expression compiles at runtime. The bundle's bytes show the two lanes: bare Function() (needs script-src 'unsafe-eval') or, if <html data-nonce> is set, a Trusted Types policy plus nonced script injection (eval-free). The main shell's CSP is strict-pinned with zero exceptions today; the ONE nonce lane is /login, minted per request for the loginpage library. Putting the product shell in nonce mode for Datastar means a third CSP posture plus nonce plumbing through layout.Base — to replace affordances shell.js already implements as 5–15 line delegated handlers (79 document-level listeners, each with a visible-surface error path per the 2026-10-27 owner ruling).

Missed opportunity · Actionable

F4 · /health keeps 'unsafe-eval' although the embedded engine can now run without it

go-health-dashboard@v0.13.2/csp.go:24 appends 'unsafe-eval' unconditionally · engine v1.0.3 nonce lane unused · webphone pin: internal/app/app_test.go:135 expects it

The dashboard library's CSP builder still adds 'unsafe-eval' ("required because the Datastar SDK" compiles expressions) — true when the lane was built, no longer true for engine v1.0.3: the same bundle now ships the data-nonce + Trusted Types path. This is the audit's only genuine gap against the library's current capability set, and it is upstream-first: go-health-dashboard would emit data-nonce on its page and grant 'nonce-…' instead of 'unsafe-eval' on the subtree; webphone then re-pins TestAppDashboardMountsHealthSubtree to assert the nonce form.

Fix Filed in TODO_LIST (2026-11-07 section): upstream change in go-health-dashboard, then flip the app_test.go:135 assertion from unsafe-eval to nonce- and keep the dashboard's eval lane gone.
Declined with reason · Low impact

F5 · templ-components/datastar rides unconsumed in the v1.27.0 pin — correctly

templ-components/datastar@v1.27.0 · indicator, live_region, loading_button, polled_region, sse_error_handling, sdk_script

The component family is one go get away, but every component drags the Datastar runtime in, and each overlaps a byte-pinned affordance: loading_button duplicates the sendIndicator one-home spinner + hx-disabled-elt pattern; live_region duplicates #toasts/#wp-live (role=status, pinned); sse_error_handling duplicates the .wp-error responseHandling contract (byte-pinned in server_test.go). The 2026-11-04 templ-components sweep's decline stance extends to these by construction.

Counterexample · Low impact

F6 · The JSON-up action model fights honest multipart — file sends are the wall

gateway seam: createFilePart (honest Content-Type, byte-pinned part headers) · compose paths: MMS attachments, fax PDFs

Datastar's backend actions are JSON-up/HTML-down, and its file binding serialises file inputs as base64 signals. The compose paths ride multipart with honest part headers — deliberately, because the Telnyx bridge sniffs only as the octet-stream fallback. Base64-in-JSON inflates multi-megabyte MMS/fax payloads by ~33% and re-encodes at the boundary; the current hx-encoding FormData path is the honest wire.

Held · Refresh trigger

F7 · Signals would buy nothing the fragment contract doesn't deliver — the live Reports tab is the canonical future trigger

Notifier.Project table (event→SSE policy) · Reports: pure projection, static by design (issue #12)

Every live surface either morphs server HTML (threads, transcript, fax, voicemail, contacts) or is media-imperative. The one signal-shaped surface webphone could grow is a live-updating Reports tab — fine-grained numeric state pushed as datastar-patch-signals is exactly what signals are for. That is the sharpened refresh trigger this report leaves behind; it does not fire today.

02What full adoption would actually cost

"Leverage Datastar fully" has exactly one coherent meaning: the island moves behind data-ignore fences / web-component wrappers, and the shell + tabs re-encode their reactive surface in data-* attributes. Priced:
