00Summary

In 2026 agents write most of the world's feature code, but the error side of software — triage, repair, verification, knowledge capture, drills — is still done by hand almost everywhere. That lag is not a capability gap: the vendor surface exists (Sentry Seer opens fix PRs from production errors, Devin and the Claude Code action can be paged on red CI, Datadog drafts postmortems, Gremlin runs agentic chaos). It is an adoption gap, and it compounds: the teams that could benefit most never built the one thing agents need to be useful on errors — machine-readable failure structure. Webphone built exactly that (total error families, stable <seam>.<op> codes, a pinned error contract, generated wire contracts), which makes the undervalued practices here unusually cheap to adopt.

The bottom line The smartest thing almost nobody does: put agents on the FAILURE side with evidence gates — a fix must arrive with a test that fails on the base commit; a diagnosis must arrive as a routed context bundle, not prose; an incident must end as a drafted ledger row, with the human owning every verdict. Six of the ten practices below are proven and cheap here; the top two (reproduce-first CI leg, main-red watcher) address this repo's two documented red-main hours-classes directly.

◆The baseline this repo already owns

Every "people don't do this" claim below is measured against this floor. Webphone's error infrastructure is, without exaggeration, the precondition most orgs lack for agent-assisted error work — stable structure an agent can grep, route, and assert against.

+
Total error families + stable codes Every error carries a family (Rejection/Conflict/Transient/ Corruption/Infrastructure/Orchestration) and a <seam>.<op> code; the registry is pinned by TestErrorCodeRegistryIsFresh, so codes cannot drift silently (docs/error-contract.md).
+
A test-pinned failure→feedback map Every user-visible failure surface (toast, banner, styled 404, 5-part boot report) has a test home named in the contract table — failures are specified behavior, not accidents.
+
Generated wire contracts + drift tests OpenAPI and AsyncAPI render from the handler DTOs; the contracts cannot drift because they are not handwritten.
+
Machine-readable operator telemetry Structured logs with error=/family= fields, honest healthz legs that name the failing check, a flight-recorder seam that snapshots >2s/5xx requests, and latency histograms — the exact inputs an agent needs.
+
Failure knowledge bases docs/lessons.md war stories, the CI-flake ledger, the dedup registry — folklore already converted to data, by hand. The agent opportunity is doing that conversion automatically.
+
Drills as tests The backup oneshot has a KVM-gated VM test covering snapshot AND restore — the precedent for asserting failure behavior under real conditions.

02Ten things agents can do that people don't

Ordered roughly by (value ÷ effort) for a repo with this error culture. Severity labels: proven (teal) = shipped somewhere at industrial scale, just not adopted; emerging (amber) = real but young.

Proven · the highest-leverage gate

P1 — Reproduce-before-fix as a mechanical gate, not a vibe

The practice: no agent fix is credible until a test FAILS on the base commit and passes on the fix

Agents graded on green CI will reach green — sometimes by fixing the bug, sometimes by weakening the test. The discipline that separates the two is mechanical: the fix PR must contain a reproduction test, and CI must verify that this test actually fails against the base commit (red → green → red-on-revert). Google formalized this as Bug Reproduction Tests: their BRT agent produced plausible reproductions for 28% of 80 real production bugs, and feeding those tests to their repair system made fixes ~30% more plausible (arXiv 2502.01821). Practitioner guides converge on the same gate. Almost nobody wires the base-commit check into CI — it is a ~40-line job.

Here: webphone already pins every contract row with a test home; the missing leg is the anti-false-green check itself — a CI job that runs the PR's new/changed tests against the merge base and requires red-before-fix (proposal R1).
Proven · and this repo holds the unfair advantage

P2 — Structured-error routing: exploit machine-readable errors

Error code in → owning package, contract row, family-test pin, lessons mentions out

Vendor triage agents work from stack traces and vibes because almost nobody has stable error codes. This repo does: every journal line carries family= and a <seam>.<op> code that greps to exactly one seam. A routing step (a script or skill: journal line in → context bundle out — owning files, the error-contract row, the family-test pin, every lessons.md mention, recent CI history for that test) turns any agent into an on-call engineer that arrives already oriented. Observability MCP servers (Datadog, Sentry, Rollbar) are the hosted version of this pattern; the homemade version over structured codes is strictly better ground truth.

Here: proposal R3 — the codes, the pinned registry, and the contract table already exist; only the router (a grep-and-assemble step, no AI even required for the retrieval leg) is missing.
Proven · tools GA, event-driven use rare

P3 — Page the agent on red CI (repair bots, not review bots)

Devin "fix CI when it fails" automations; Claude Code Action automation mode reads CI results; Codex Fix-in-Checks

Teams deploy passive review bots everywhere but almost never the active loop: main goes red → an agent is dispatched → it reproduces locally, classifies flake-vs-real against history, and returns either a fix PR with an evidence pack or a diagnosis that says "not a code problem". The capability is GA at multiple vendors; the trigger discipline is what nobody builds.

Here: the cost is documented: main sat red ~4h (2026-10-05) and ~2.5h (2026-10-24, unregistered error codes), and the daemon-reflow race class recurred across 2026-10-12. A scheduled watcher that runs the flake-ledger check first and only then dispatches a fix session would have converted both incidents into minutes (proposal R2).
Proven · the counter-intuitive half is skipping autonomy

P4 — Flake forensics as auto-documentation, not auto-quarantine

BuildPulse/Trunk/Datadog detect and quarantine; the smart part nobody does is drafting the VERDICT row

Auto-quarantine is the commodity; it also has a documented trade-off (blanket auto-retry can turn real bugs green). The underused move is the opposite of autonomous: after a suspected flake, an agent assembles the DRAFT ledger row — run id, failing test, duration, same-commit pass/fail evidence, similarity to prior rows ("same class as run 38245220074?") — and the owner rules the verdict. Folklore-to-data stops depending on a human remembering to write it down at 2am.

Here: docs/ci-flake-ledger.md is exactly this table, hand-maintained since 2026-10-06. The agent drafts; the verdict column stays human (rides R2).
Proven pattern · novel target

P5 — Contract-chaos drills: assert the SHAPE of failure, not its absence

Inject the failure; assert the contract held (fail-closed 503, honest healthz, styled 404, 5-part boot, redaction)

Chaos engineering asserts liveness under failure. The agent-era upgrade asserts your ERROR CONTRACT under failure: kill the database mid-write, blackhole webhook egress, corrupt a blob, wedge the health probe — then assert fail-closed (not fail-open), the healthz leg naming the failing check, the styled 404 for browsers vs terse answers for machines, the 5-part boot report, and SafeDetail redaction. Most orgs cannot do this because they have no contract to assert. Gremlin's agentic Foresight loop is the hosted version of this idea; the homemade version is just a test.

Here: the backup-drill VM test is the standing precedent — an error-contract drill check generalizes it (proposal R4). Bonus: the 2026-10-24 lesson (a lowercased OpenAPI method key slipped past the CSRF gate and false-greened a drift test) is precisely the class adversarial probing catches.
Proven · vendors ship it, small repos never close the loop

P6 — Telemetry→knowledge closing: auto-drafted war stories

Datadog drafts postmortems with accuracy disclaimers; incident.io's stance is "exoskeletons, not robots"

After an incident, the expensive artifact is not the fix — it is the write-up that prevents round two. Agents can now assemble the draft mechanically: flight-recorder snapshots, the metric window, the git context, the timeline from structured logs, the recurrence check against past lessons. The human owns the verdict and the blameless-analysis judgment; the blank page is gone.

Here: the flight recorder + structured logs + latency histograms are the inputs; lessons.md rows are the hand-written output today (proposal R6).
Proven · uniquely cheap with prose lessons

P7 — Recurrence detection: "known lesson violated" beats "new bug"

Every new incident matched against the lessons base before it is treated as novel

Knowledge bases accrete precisely because nobody rereads them at incident time. An agent sweep that takes the failure signature and asks "which past lesson does this resemble?" converts a prose archive into a live classifier — and when the match hits, the finding escalates as a recurrence (the root-cause write-up already exists) instead of being re-diagnosed from scratch.

Here: the whitespace-drift class alone has 3+ entries (the e62fe34 red, runs 38245220074/38255111611); every one was re-diagnosed by hand. A red-CI first step of "grep the ledger + lessons for this signature" (rides R2) makes the recurrence check free.
Proven · Anthropic's own verification-tier ladder, applied to prose

P8 — Error-prose gates: an LLM judges user-facing copy against the empathy contract

Structural linters check codes and families; nothing checks the WORDS

Anthropic's verification ladder is: rules first, visual feedback second, LLM-as-judge last (least robust). For code that is right. For PROSE the ladder inverts — no rule can tell whether an error message answers what happened, reassures, explains why, gives a fix, and offers an escape; an LLM judge can, cheaply, on the diff only. Nobody runs this gate. It is the rare case where LLM-as-judge is the correct tool, not the lazy one.

Here: the 5-part contract (What / Reassure / Why / Fix / Escape) is already the rubric, and erraudit already holds the structural half at zero. A detect-only, changed-strings-only prose gate matches the repo's tier-3 owner-only bar (proposal R5).
Emerging · the pattern is sound, full autonomy is hype

P9 — Evidence-gated autonomy tiers (test diffs are the riskiest diffs)

Mechanical fixes may merge behind full gates; auth/session/migration fixes stay proposals forever

The emerging convention for agent PRs: an evidence pack (failing run id, reproduction test, exact commands, rollback one-liner, previous green SHA) plus risk tiers where high-risk paths — auth, payments, migrations — are draft-only, and where TEST diffs are treated as higher-risk than production diffs, because a green suite that no longer guards the bug is a false green. Fully autonomous merge for medium/high risk remains hype; every serious vendor keeps human merge authority.

Here: the tier already exists culturally — the auth: commit prefix + mandatory session-behavior suite is a risk tier in all but name. Formalizing it as an agent policy is mostly writing down what the repo already enforces on humans (rides R1/R2).
Emerging · the meta-inversion

P10 — Agent-reliability engineering: apply your error contract TO the agents

Idempotent side effects, journaled checkpoints, compensation semantics, stopping conditions, durable human pauses

The spicy version of this whole report: people deploy agents with zero of the error discipline they would demand from a payment flow. The 2026 playbook exists — durable execution (Temporal/ Restate journal every step; never re-execute a side effect on replay), idempotency keys, compensation ("undo" defined before ship; irreversible actions routed through human gates), stopping conditions, verification after every action. Git itself is the poor man's journal: small committed units ARE checkpoints, and a PR IS a durable human-approval pause.

Here: the repo's own patterns map one-to-one — hooksIdem is exactly-once by another name; the release ritual's rollback legs are compensations; the auto-commit daemon is the live specimen of an unmanaged agent (it ate 69 skip_steps lines once, and its commit-msg guard hole is documented). A watchdog leg that audits daemon commits — whitespace-drift check, .buildflow.yml diff audit, push-stall anchor — is watchdog-on-watchdog (proposal R7).

04What NOT to do (the hype flags)

Every capability above has a failure mode the vendors themselves warn about. The 2026 line between smart and reckless:

Auto-merge beyond mechanical risk

Vendors that automate diagnosis aggressively still keep human merge authority. Auth/session/CSRF/migration fixes from agents unattended is the documented false-green / review-skill-atrophy failure mode, not a bold move.

Auto-retry/auto-quarantine that masks real bugs

Blanket test retries turn some real bugs green (documented Datadog trade-off). Quarantine decisions need the verdict discipline of the ledger, not a rate threshold alone.

Sign-off-free postmortems

LLM postmortem drafts ship with explicit accuracy disclaimers. Letting one be the record, rather than the draft, encodes plausible fiction into institutional memory.

Agents editing tests to reach green

The highest-risk diff in any agent PR is the TEST diff. Treat test changes as adversarial until proven reproducing (that is exactly what R1 operationalizes).

Unbounded loops & unmanaged agents

No stopping conditions, no idempotency, no compensation — the auto-commit daemon's incidents are the local proof. Deploying an agent without ITS error contract is the meta-failure this report's P10 exists to prevent.
