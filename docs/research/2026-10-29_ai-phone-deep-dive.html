00Summary

ai-phone is a two-day-old public repo (created 2026-10-27, 124 stars and 23 forks at this snapshot) whose documentation set is unusually mature for its age: a ~1,200-line architecture.md, a read-first architecture-essentials.md that declares six numbered invariants as settled, and a decision log where every row is tagged [D] decided, [P] proposed or [V] verified against source. It is a different product from webphone (server-side SIP, local MLX models, one call at a time, no browser UI), which is exactly why it is worth reading: its problems are webphone's problems at a different layer, and where it solves them it does so with mechanisms, not slogans.

The bottom line The single most transferable thing in the repo is not telephony. It is the habit of pairing every claimed invariant with the mechanism that enforces it, and then pinning the prose to the code so the claim cannot rot. Two of those pairs were missing here and are shipped now: a docs-versus-code pin over the configuration table (which immediately found eight undocumented config keys) and a generation-closing rule for live transcripts that race a hang-up. The remaining five actions are filed, ranked, with the sharpest one being that this repo’s config silently ignores typo’d keys in both the JSON file and the environment.

Fit, stated up front: webphone’s ratified ruling stands — all Go-side telephony is rejected, the stack owns SIP and FreeSWITCH, the island is the phone. Nothing here reopens that. What travels is discipline about asynchronous audio, about what a “settled” artifact is, and about the config and documentation surfaces that decide whether an operator’s intent reaches the running process at all.

◆The baseline this repo already owns

Every mechanic below is graded against what webphone ships today, so this list is not a to-do written from ignorance. Verified in this session against source:

Error family + codes. Total families, stable <seam>.<op> codes, a generated registry block and a freshness test. ai-phone reports exit codes and prose; the machine-routing surface here is ahead.
Seam gating with fail-closed halves. CRM, Paperless, ASR, textagent, Matrix, Signal, push and both auth lanes each refuse a half configuration at boot, and each seam is byte-identical when unset. ai-phone’s unknown keys are errors rule is the one piece of that doctrine this repo has not adopted.
Owner scoping and durable records. Every query is extension-scoped; transcripts, notes and agent audits live in owner-keyed stores. ai-phone’s trust boundary is a 0600 unix socket for a single user.
Gates. nix flake check (package, tests, treefmt, island-lint, island-typecheck, module eval, KVM-gated backup drill), plus a duplicate baseline and the erraudit tiers. ai-phone’s CI is two macOS jobs and pytest.
Caller-data doctrine. Local ASR preferred, US-inference APIs ruled a GDPR no for caller audio. ai-phone reaches the same conclusion from the other direction (offline model, no runtime downloads, no telemetry) — useful prior art, not a new ruling.
Asynchronous transcription is already careful. Four-second MediaRecorder segments, a near-silence gate before spending a request, a shared 429 cooldown, exponential backoff, a bounded per-call save queue and a bounded caption strip. Almost every “audio is unreliable” lesson in ai-phone has a counterpart here.

01What ai-phone actually is

One daemon, one or more SIP lines, one call at a time across them. It registers to a trunk or answers at a plain SIP address, then runs speech-to-text, a language model and text-to-speech on the host by default. The layering rule is the load-bearing part: L1 knows nothing about models, L3 knows nothing about SIP, L2 owns the conversation.

Layer What it is Discipline
L1 telephony PJSIP 2.17 via pjsua2, SWIG extension built on the host by the install script; null audio device; media port at 16 kHz The PJSIP thread never blocks: media callbacks copy 640-byte frames into 2-second shared-memory rings and return
L2 pipeline Hand-rolled asyncio TurnController: VAD, endpointing, barge-in, clause chunking, resampling, timers Owns the conversation state machine and every timer; one controller per call
L3 workers Three child processes, one model each (parakeet STT, Qwen3.5 4-bit LLM via mlx-lm, Kokoro or Phonon TTS) Audio crosses in shared memory, never pickled; control is JSON; a crashed worker is restarted, capped at three per ten minutes
L4 control Unix socket at mode 0600, newline-delimited JSON, one request per connection; CLI is a thin client Every request shape-checked before the daemon sees it; the daemon, not the server, decides “busy”

The measured numbers matter because they are stated against a budget rather than as marketing: the M1 gate measured 874 ms p50 / 1438 ms p95 from last speech to first audible RTP frame over 20 LAN calls, and the README publishes the latest run at 1.50 s median under memory pressure, which missed the one-second target. That is the same posture webphone’s honesty contract demands of its own surfaces, applied to a README.

02Ten mechanics, graded against this repo

L1 · ADOPTED TODAY

Pin the prose to the code, or the prose will lie

tests/unit/test_docs_match_code.py names the model catalog in three documents, holds one extraction pattern per place, and fails when any of them drifts from models.CATALOG. Three details make it good: each failure message carries a “if the wording moved, move this test’s pattern with it” hint; a belt-and-braces test asserts the three documents agree with each other, so a pattern pointed at stale text cannot pass silently; and a fourth test asserts the keys are shaped so the patterns can match them at all.

This repo had one such lane (the generated error-code registry) and none over its largest documented surface: the configuration table. Shipped in this session as internal/config/docpin_test.go with three assertions — every documented key exists as a koanf path in the struct tree, every leaf key appears in an operator document, and the config-owned defaults match the table. It found eight undocumented keys on its first run (see Shipped today). Both arms were proven load-bearing by breaking them deliberately: renaming one documented key and deleting one documented row each failed the right test with the right message.

L2 · ADOPTED TODAY

Every asynchronous generation has an id, and stale results are dropped

ai-phone’s fourth invariant: every generation carries a gen_id; cancelling means all three workers drop that id, the outbound ring is flushed, late results with a stale id are discarded, and the partial reply stays in history marked [interrupted] so the model knows what the caller heard.

webphone already keys transcript segments by call id, so attribution across a hang-up was safe. What was missing was the other half: a segment still in flight when the call settled still repainted a live surface — it announced a caption for a call the operator had hung up, and re-created the call’s in-memory segment log, one entry per call, for the rest of the tab’s life. Shipped: closeCallSegments closes a settled call’s log to late writes (a new capture for the same id reopens it), and the per-segment announce now requires the entry to still be in the session map. The segment itself still saves: the audio really was heard, and the durable History row wants the tail. Two pins cover both halves, including the assertion that the tail reaches /api/transcripts with the right call id.

L3 · OPEN

Measure latency from the caller’s clock, not the server’s

Its t0 is the timestamp of the last VAD-positive chunk, not the moment the endpointer fires, and the report states why: “the 300 ms of silence is inside the budget, not excluded from it.” Every turn writes one JSON line with five stage timestamps plus overrun and underrun counters, and a small script prints p50/p95 per stage for the gate.

webphone measures HTTP request durations into a histogram and request counts by status class. Both are honest and neither is what the person holding the phone experiences. There is no “dial press to first audible media” number anywhere, and the ASR segment round trip — the thing that decides whether captions are live or a transcript — is untimed. Filed as an open action, not implemented: a per-call media metric needs island work and a decision about where it is reported.

L4 · VALIDATED
An invariant without a mechanism is a wish. Each of the six invariants names its enforcer: the ring buffers for “the PJSIP thread never blocks”, the gen_id for cancellation, turns.jsonl for “measured, not claimed”. webphone is largely built this way already (machine tables own lifecycle legality, an arch test owns the module graph, the DOM contract is parsed by a test). The value of the comparison is the two places it is not yet true, both listed here: config typos (L7) and caption drift (L8).
L5 · NOTE FOR D3

Enforce safety at the chokepoint every client shares

Emergency numbers are refused and the daily limit is counted in the daemon, with the reason written down: “so every client is covered”. Two details are worth more than the rule. First, the counter is reserved before the act and written atomically (temp file, fsync, rename), malformed reads as zero, and if the count cannot be written after dialling, the call is hung up immediately and refused — no attempt escapes the budget. Second, a control-socket client cannot talk its way past it; the server only validates the shape of a request, the daemon owns the claim.

webphone already puts refusals at the deepest seam (SelfSendRejection in the gateway, session gating in the handlers) rather than at the route. The transferable part is for the planned agent-token lane (D3): scope enforcement has to live where every caller passes, and a budget that cannot be recorded must refuse the action rather than optimistically proceed. Recorded, not filed separately — D3’s owner call and security review still gate it.

L6 · OPEN (D3 input)

A remote brain needs a liveness contract, not a timeout

Relay mode lets any shell-capable AI hold the conversation: one JSON object per command over the local socket. The interesting part is what happens when the AI stalls or dies. The caller hears “One moment.” at 1.5 s, “Still with you, one moment.” at 10 s, then a polite goodbye and BYE at 25 s. A dead listen client frees the listener slot the moment its socket reports EOF, so the next incoming call falls back to the autonomous agent instead of queueing behind a corpse. hangup waits 30 s and then 10 s more, and fails with a named exit code rather than pretending.

webphone’s textagent seam has a bounded 3-second probe and a visible 502 toast, which covers “the agent is unreachable”. It does not cover “the agent accepted the request and then went quiet”, and there is no designed fallback for the human waiting on a draft. Filed as an open action to shape D3’s liveness rules from this prior art before the agent-token design is built.

L7 · OPEN · SHARPEST GAP

Unknown configuration keys must not be silent

ai-phone validates a typed schema at startup and “unknown keys are errors”. webphone loads through koanf and Unmarshal at internal/config/config.go:594, which quietly drops any key it does not recognise, from the JSON file and from the WEBPHONE_* environment alike. The consequence is the worst failure shape this codebase has: a typo does not fail the boot, it turns a seam off. Write WEBPHONE_ASR__TOKEN after mistyping the URL and the half-configuration refusal fires loudly; mistype the token key itself and the provider is simply anonymous, or the seam simply never enables, with no line anywhere saying so.

Filed with the design already constrained: strict for the config file (a closed namespace, an operator’s hand-written artifact) and warn-only for the environment, because a dozen operational WEBPHONE_* variables are not config keys at all (WEBPHONE_CONFIG, WEBPHONE_DEBUG_TIMING, WEBPHONE_RELEASE_MAX_LOAD and friends), and a false reject there would be an outage on every deployment. The NixOS module writes a freeform settings map, so the file half is an owner call: it changes boot semantics for a deployment that carries an extra key today.

L8 · OPEN

Count the things you would need in an argument

Receive overruns, transmit underruns, per-stage milliseconds, warm-start timings and a resident-memory check are all part of the turn record, because each one answers a question somebody will eventually ask under pressure (“is the model too slow, the network, or the disk?”).

webphone’s live transcription has one invisible failure class of exactly this kind: if the provider takes longer than the four-second segment cadence, segments queue in the recorder and captions drift further and further behind the conversation with no counter, no warning and no timestamp on the segment path. Everything else about that loop is careful (silence gate, cooldown, backoff, bounded queues), which is what makes the missing lag measure stand out. Filed as an open action.

L9 · VALIDATED, one gap
Failure tables need a detection column. ai-phone’s §13 lists every failure with Detection and Recovery; webphone’s docs/error-contract.md maps failure to visible surface. Those are different questions. “What does the operator see” is answered well here; “how would anyone know it happened” is only answered where a counter or a probe exists. Worth adding a detection column for the silent classes at the next pass over that document, with L8’s caption drift as the first row.
L10 · VALIDATED
Publish the rejected alternatives, and the number you missed. The stack table carries a “Not this” column naming the libraries that were evaluated and dropped (pyVoIP, Asterisk, LiveKit, Pipecat, Ollama), each with the reason that killed it; the decision log records reversals with the date. The README states the missed latency target in the same sentence as the passing ones. Both habits match what this repo already does in its research reports and its honesty contract — read it as confirmation that the style survives contact with a second author, not as a new rule.

05What does not transfer

The stack

Python, uv, a locally built SWIG extension over PJSUA2, MLX models, an AGPL-3.0 licence, macOS on Apple Silicon only. None of it can live in a single-binary Go deployment, and the GPL lineage of PJSIP would relicense the product. The architecture is the lesson; the implementation is a different animal.

Server-side call control

Its whole model is a daemon holding the SIP dialog — including a one-call-at-a-time lock across all lines. webphone’s island holds several calls at once and the stack terminates SIP. Adopting the lock would be a regression; adopting the layering rule would not.

Its trust model

One user, one 0600 socket, transcripts readable by any process of that user, English only, no account model, no roles. This repo is multi-actor with owner-scoped stores, passkey/OIDC identity and a durable agent-audit journal; that distance is the product.

Its configuration surface

One YAML file with a typed schema is a clean place to demand strictness. webphone’s surface is environment plus JSON plus a freeform NixOS settings map, which is why L7 lands as two rules with different severity rather than one.

Its latency budget

Mouth-to-ear depends on local models and a phone leg. The number that matters here is the ASR segment round trip against a remote provider, and it is bounded by a different physics: four-second segments, one HTTP request each.

Its docs volume

A 1,200-line architecture document works for a project with one author and no module boundaries. This repo already answered that question differently: a capped AGENTS.md of rules with evidence moved into docs/. Copy the routing table, not the length.
