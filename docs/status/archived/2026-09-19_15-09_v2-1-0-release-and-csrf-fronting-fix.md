## d) TOTALLY FUCKED UP

1. **Production tab logins are broken RIGHT NOW (since ~2026-09-18).** Every browser login POST on `pbx.artmann.tech` gets 403 (`csrf.origin_attestation_conflict`): TLS ends at nginx, the listener sees plain HTTP, so the truthful `Origin: https://…` reads as a forged same-origin attestation. **Severity: blocks all users** — messages/fax/voicemail/history/contacts tabs never unlock; calls keep working (island is server-independent), which is exactly why nothing screamed. Root cause: httputil attestation check + unconfigured `CSRFConfig{}` (scheme-only mismatch; `X-Forwarded-Proto` is only honored from _trusted_ proxies). **Fixed in v2.1.0 (`csrf.trusted_*`), but NOT YET DEPLOYED.** Workaround on the deployed build: none. The 2026-09-19 server-side probes (healthz/config.js/hooks) passed _because they never exercise a CSRF-gated POST_ — a false comfort.
2. **The stack browser E2E was green while logins were broken.** The E2E tolerates `POST /api/session` 403s (the island's session creation is deliberately non-fatal; no marker asserts a 201). A "green" regression gate shipped and kept shipping a product whose tabs never unlocked. This gate blind spot is arguably worse than the bug itself. (Session finding; not yet fixed — see f3.)
3. **Session-internal own goals (all caught before push, listed for honesty):** a stray `http.Error = nil` line from a multiedit (build caught it in <1 min); a `htputil` typo (build); the new module settings hit the **documented** statix single-assignment trap (AGENTS literally warned about repeated `services` keys — buildflow caught it during the release gate, costing one extra full gate cycle); my fronting test first asserted 201 for _both_ subtests; and one false nondeterminism scare caused by my own grep mixing two different test runs' output.
