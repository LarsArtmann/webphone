## e) WHAT WE SHOULD IMPROVE (process, from this session)

- **Preflight gates BEFORE release.sh, always.** The script's fail-fast design is for MID-run surprises, not for known-gate state. A "release preflight batch" (buildflow + race suite + lychee + docs battery) run once before attempt 1 converts the release from an explorer into a verifier. This is the single highest-leverage change this session's evidence supports.
- **The docs battery is a pre-push gate for ANY markdown edit, not a CI discovery lane.** "Markdown is formatter-unowned" (treefmt) is true and dangerously incomplete as a mental model — dprint owns the bytes and the battery enforces them. Habit to install: `nix develop -c scripts/docs-gates.sh` between every docs edit and every push.
- **Read the failure output FIRST, hypothesize SECOND** — even when a documented trap (GOEXPERIMENT) fits the smell. The transcript evidence lives in the log; the trap list is a hypothesis generator, not a diagnosis.
- **Hand-commit lock moves in the SAME tool call as the flake update.** The daemon-vs-hooks hole (GIT_CONFIG override) means any lock change left uncommitted for one daemon cycle gets an unattributed sweep commit that (a) fails CI's lock-guard later and (b) looks hostile to every other session watching. The release-runbook ritual already says this; this session proves the cost of not doing it atomically.
- **Cross-session lock intent needs a marker in the TREE, not just in the chat.** The other session's revert was reasonable given what they could see. If release.sh's step 7 left its intent in a file (or committed atomically), the collision never happens. Candidate: a `.relock-in-progress` convention or simply the atomic commit itself.
- **Archive-ritual link rot is systematic** — every `git mv` into `archived/` breaks sibling relative links, and the lychee gate only catches them at release time. The docs-health archive step should run lychee on the moved file's directory as part of the ritual (or a weekly lychee in CI would catch the class within days instead of at the next release).
- **The private-repo link class is now config-documented** (`lychee.toml` with the verified-live reasoning in its header) — the same pattern should cover future private-repo references so the exclusion list carries its own evidence.
