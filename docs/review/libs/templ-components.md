## 2026-11-22 re-verify — v1.27.1/v1.27.2 adjudicated: bump DECLINED

Both patches were read against what webphone actually renders (rg first), not against the changelog headlines:

- **The CSP/grid conflict is N/A — webphone renders no auto-fit grid.** Since v1.27.1, `display.Grid`'s `MinColWidth` mode carries the width as an INLINE STYLE ATTRIBUTE (`style="--tc-grid-min:190px"`, display/grid.templ:92-97) — a documented upstream CSP exemption, but webphone's `style-src` has no `unsafe-inline` (AGENTS.md: "NO inline style (silently dead)"). Evidence it cannot fire here: `rg "display\.Grid|MinColWidth|tc-grid-min|GridColsAutoFit" internal/ cmd/ scripts/` → **0 hits**; none of the consumed components (layout.Base, Button, EmptyState, Badge, DefinitionList, Input, Textarea, Icon) renders the grid internally (the library's only in-repo Go caller is its own `website/`); and the tw.css @source allowlist (`internal/web/assets/tw.css.input:112-131`, staged by `scripts/build-tw-css.sh:122-137` from the module cache) does not even list `display/grid.templ` — the inline style has no path to a webphone page. If a future panel ever adopts `display.Grid`, the bump calculus flips AND a `style-src` decision lands with it.
- **The v1.27.2 security fix has no attack surface here.** `rg -i "ld\+json|breadcrumbJSONLD" internal/ cmd/` → **0 hits** (the only "breadcrumb" in the tree is a shell.js:183 comment about the island event log): webphone renders no breadcrumbs, no ld+json block, so the `</`-escape fix protects a surface that does not exist (defense-in-depth only). Same for `utils.ScriptComponent`'s new `</script>` refusal — zero call sites in webphone (toasts are island-owned `#toasts`).
- **The v1.27.1 templ-pairing incident did not touch webphone.** The library's own CI regenerated committed `*_templ.go` with templ v0.3.1020 against the v0.3.1100 pairing; consumers were affected only if they regenerated against the broken committed files. Webphone regenerates views with its own CLI at templ **v0.3.1118** (go.mod:6 — AHEAD of the library's pairing), and the staged tw.css build reads `.templ` sources from the module cache, never committed `_templ.go`.
- **What a bump would actually carry for the consumed surface — small but not zero-cost.** Source diff v1.27.0→v1.27.2 over the @source allowlist: badge gained the shared-line dot+text (copied badge text no longer starts with a space — cosmetic) and remapped `BadgePrimary` blue→accent — inert here, because `faxBadgeType` uses Warning/Success/Error/Neutral only (fax.templ:252-261) and webphone's tw.css.input remaps `--color-blue-*` onto the accent tokens in the OPPOSITE direction; forms Input/Label/Textarea gained the opt-in `Stacked` prop (default sibling shape byte-identical); layout/base, empty_state, button, definition_list, icons/icon: **0 source diff**; feedback/loading.templ (staged for login.css) was reworked by the LoadingProgress extraction. The repo rule still applies: a bump rides the tw.css/login.css rebuild (`scripts/build-tw-css.sh --check` is the drift gate) + views regen — a real train for a fix webphone cannot exercise. **Adjudication: DECLINE the standalone bump; adopt v1.27.2+ when the next templ/tw.css train runs for its own reasons.**

## Errata — the four red rows ruled (2026-11-04 closeout train)

- **Status badges: PARTIAL.** `FaxStatusBadge` now renders `display.Badge` (tone table `faxBadgeType`, localized label via the existing `faxStatusText`, `Dot: true`; tw.css gained the badge @source pair). **`OutboundStatusBadge` DECLINED with evidence**: the `wp-status-*` classes are byte-pinned ×5 in `messages_test.go` (guard §5.3) INCLUDING the delivered `aria-hidden="true">✓` checkmark — an asserted affordance with no Badge slot — and the classes are bubble-INTEGRATED DOM: `.wp-bubble.wp-out:has(.wp-status-failed)` drives the failed bubble's border/meta styling (app.css:1906-1944). Swapping means reworking the bubble component and deleting a pinned affordance — a product redesign, not a library adoption. The owner's documented deliberate-hand-roll boundary (AGENTS.md: nav badges et al.) already covers this class.
- **feedback.Alert: DECLINED with wire-contract evidence.** `.wp-error` is not styling — it is the htmx `responseHandling` SELECTOR (`"select":".wp-error"`, pinned in `server_test.go:391`) by which the island's error swap finds 4xx/5xx panel bodies, plus literal `class="wp-error"` pins in `messages_test.go:206` and `textagent_api_test.go:251`. Alert composes its own classes into the class attribute (the pinned literal is the FULL attribute value) and renders a different role/structure; a swap rewrites the island's error contract + three pins for zero user-visible gain. AGENTS.md's deliberate-hand-roll list already covers the error panel; the errorpage module was REJECTED on the 09-22 deep-dive for the same territory.
- **panelHead → PageHeader: DECLINED — the finding targeted a non-duplication.** `views.panelHead` is already the documented ONE home (AGENTS one-home list) for all 7 panel headers; PageHeader would replace ONE function, not duplicated markup. Its `wp-panel-head` class carries contracts: `sse_test.go:73` pins it as a FORBIDDEN fragment string (SSE payloads must not re-render the head), app.css styles its h2/sub shapes, and `shell.js:1444` focuses `#tab-content h2` after EVERY tab navigation — the h2 inside this header is the accessibility focus target. A swap risks the focus move silently breaking for zero class-consistency value.
- **SimpleEmptyState: PARTIAL — 2 of the 11 `wp-empty` sites.** The audit's "×10" was a grep-driven overcount: T09's per-site triage found 4 are section SUBTITLES (`audit.subtitle`, `passkeys.subtitle`, `snippets.subtitle`, the theme note), 2 embed `<code>` elements (history + voicemail disabled notices — SimpleEmptyState takes only a string), 2 carry ids pinned by tests or JS (`wp-passkeys-empty` is asserted in `passkey_api_test.go:488`; `wp-agent-audit-empty` is an id hook), and 1 carries `role="note"` + the `wp-fax-off` capability class. The two TRUE empty states (push devices empty, snippets empty) swapped; the nine others are semantically not empty states or structurally un-swappable. Refresh trigger: an owner taste ruling that wants subtitles styled as muted empty-states (a presentational change, not an adoption gap).
- Refresh trigger for the messages badge half: an owner taste ruling that accepts losing the ✓ chip (or Badge growing a prefix/icon slot) AND a train that rewrites the five pins deliberately.

## Ruling

The thin-but-deep pattern is right for a domain-specific phone shell — do NOT chase component coverage for its own sake. ~~The four red rows are worth a small train~~ **RULED 2026-11-04**: fax badge adopted + 2 true empty states swapped; messages badge, error banner, panelHead, and 9 empty-state sites declined on pin/contract/structural evidence (errata). Each keeps the cascade-layer contract (layered utilities only) and the greppable row classes.

**Refresh trigger:** a templ-components release with a new status/toast component; any panel redesign; the error surface train revisiting banners; a consumed component ever needing the auto-fit grid or a breadcrumb surface (either flips the 2026-11-22 decline — the grid brings the inline-style exemption into webphone's no-inline-style CSP, the breadcrumb makes v1.27.2 load-bearing); the next templ/tw.css train picking v1.27.2+ up as a passenger (no standalone bump warranted).
