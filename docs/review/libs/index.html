02Findings — top opportunities (impact × ease)

Six actions, sorted by impact then ease. Each links to its evidence.

High impact · Low effort

Adopt go-atomic-write for blob persistence

internal/blob/store.go:50 · cmd/webphone/catalog.go:56,64 · cmd/webphone/contracts.go:36

The blob store saves attachments and fax PDFs with a bare os.WriteFile(abs, content, 0o640) — no fsync, no atomic rename. Write ordering verified file-then-row at all four call sites (T01 errata), so the precise window is row-committed-before-file-durable: a power loss after the database row commits can leave a truncated blob behind a row that references it: user data that 404s (inbound faxes: the only copy). This is the only user-data durability hole found across all 25 libraries (LANDED 2026-11-04). The CLI spec writers get WriteIfChanged (no torn diffs, no mtime churn) in the same move. Ride the vendorHash re-pin ritual in the same commit.

Fix atomicwrite.Write(abs, content) in blob.Save (content is already in memory), WriteIfChanged for the two CLI writers. Full analysis: go-atomic-write.md
