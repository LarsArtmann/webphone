00Summary

WebPhone's frontend is far better than “works” — it has an actual point of view. The desk-phone vernacular (one teal accent, flat rows in quiet panels, a single “line light” motif echoed across three indicators, keys that answer the hand) is applied with a token discipline most design systems never reach, and the honesty doctrine — the UI never shows a state the network has not confirmed — is visible in the shipped product, not just in docs. The visual harness passed all its layout assertions across viewports, and every theme pair I measured passes WCAG contrast — with exactly one systematic exception.

That exception is the finding that matters: in the dark theme, every accent-filled surface fails WCAG AA for its own text — the primary Call/Send buttons, the outbound SMS bubbles, and the failed-send bubble all print near-white ink on bright green/red fills at 1.9–3.2:1, and the hover state is the worst of all. One token flip fixes the entire class. Behind it sit consistency gaps, not defects: a meta theme-color that drifted off the palette, one service row missing its status dot, English mixing 12-hour and 24-hour clocks between panels, and empty states whose helpfulness varies by tab.

The bottom line Ship-quality UI with one systematic dark-theme contrast failure (fix: flip dark --on-accent to dark ink — one token, every filled surface, both stylesheets) plus a short polish queue. Nothing here blocks a release; the contrast item is the only one a top-tier reviewer would call a defect.

◆What's already excellent

Before the criticism: acknowledge what works. This builds trust and keeps the report from reading like a pure complaint list.

+
A real design language, not a template Desk-phone vernacular executed deliberately: one teal accent, flat rows in quiet panels (a hairline earned on hover, never box-in-box), keypad keys with gradient faces and a press answer, and one "line light" motif — the glowing LED dot — echoed exactly three times (registration pill, the #wp-sse-live dot, call-state dots). The CSS comments argue their choices; the product matches them.
+
Contrast discipline, measured Every measured token pair passes WCAG except the one systematic dark-fill case in Finding 1: muted text 6.9:1 dark / 5.9:1 light, warn 8.3 / 5.4, danger 5.9 / 4.8, avatar and accent combinations all above 5:1. This is engineered, not lucky.
+
Layout asks the container, not the viewport The .wp-main-col container query (tabcol) is the modern-correct architecture for a collapsible side panel, and the harness proved it end to end: collapse, persistence across reload, and the Messages master–detail split threshold all PASS at six viewport widths. :has(.call-card) force-re-expands the island so a live call can never hide — state encoded in CSS, not JS bookkeeping.
+
Honest UI is visible in the product The offline banner flips exactly with registration truth; the fax tab offers a compose form only when the server can send; Settings reports "caller audio is processed on this server" next to the transcription state; the 404 echoes the mistyped path and hands back the way home. The written doctrine is observable in served bytes.
+
Reduced motion is complete, including JS-triggered classes Beyond the global guard, the island separately kills the state pulses, the key-sent flash and the held-blip — every animation the JS can set has a CSS reduced-motion answer, so the JS itself never animates.
+
The root font size is a percentage, and the whole scale rides rem html { font-size: 93.75% } keeps every size tracking the user's browser preference (a px root would pin it), font-synthesis: none prevents fake bold, and fluid clamp() display sizes stay inside the rem scale. Text-scaling users keep the layout.
+
Pre-paint state, storage-failure safe theme-preload.js applies theme, collapsed island and dismissed welcome before first paint (no flash, no layout snap) and a failed localStorage read simply rides the OS theme — private mode degrades gracefully.
+
The empty states teach Voicemail's seam-off empty state is the model: what it is ("Voicemail lives on the PBX"), who acts ("Ask the operator to enable the phone API"), and what happens after ("messages will appear here and in the phone panel"). Snippets, fax and the welcome intro all point at the next action.

01Findings

These are the issues that need attention, ordered by impact.

Defect · WCAG AA failure, dark theme

Every accent-filled surface prints unreadable ink in the dark theme

app.css:23-26 + island/style.css:17-20 (token blocks) · button.wp-primary, island button.primary, .wp-bubble.wp-out

In the dark theme the accent fill is a bright green (--accent: #17a467, hover --accent-strong: #3fd694) while --on-accent stays white. Measured: 3.21:1 white on #17a467 (fails the 4.5:1 AA bar for normal text), dropping to 1.87:1 on hover — the button gets harder to read the moment you reach for it. The same two tokens paint the outbound SMS bubble (white body text 3.21:1; the timestamp/status meta at 78% opacity falls to 2.52:1) and the failed-send bubble (white on --danger #ef6a5f, 3.04:1; its meta 2.46:1). This is the Send button, the Call button, and every message the user sent — the most-read surfaces in the product. The light theme passes everywhere (white on #0e8752 = 4.56:1), so the defect is dark-only and systematic: one token pair, five surfaces. 

:root, :root[data-theme="dark"] {
  --accent: #17a467;
  --on-accent: #ffffff;   /* 3.21:1 on --accent — fails AA */
}
Fix: flip the dark theme's ink, not its brand Keep the vivid dark-theme accent and switch dark --on-accent to a dark ink (the --bg value): 6.06:1 on --accent, 10.42:1 on --accent-strong hover, 6.39:1 on --danger — every filled surface passes at once, and a lit key with a dark legend matches the hardware-phone vernacular the island already speaks. The flip must land in BOTH mirrored token blocks (app.css and island/style.css keep the tokens in sync by rule). Alternative: darken dark --accent to ~#108351 (white 4.79:1) and add a darker hover — more churn, dimmer brand.
Important · brand-color split brain

The browser/PWA tint is a teal that exists nowhere in the app

layout.templ (ThemeColor/DarkThemeColor) · manifest.webmanifest (theme_color/background_color)

Both the meta theme-color and the manifest name #0f766e — Tailwind's teal-700, a color the design system never uses (the accents are #17a467 dark / #0e8752 light). Installed as a PWA or viewed on mobile, the browser chrome tint visibly disagrees with the UI beside it. background_color / DarkThemeColor use #10161a against the real --bg #0b0d11, and the manifest splash color is fixed dark even in light mode. Two homes carry the wrong value in lockstep.

Fix Point layout.templ and manifest.webmanifest at the real tokens: #0e8752/#17a467 for theme-color and #0b0d11 for the dark background — change both files together, they are the same fact.
Important · destructive-action ambiguity

Icon-only actions lean on hover tooltips; destructive-looking icons sit beside utility icons at equal weight

ThreadView head (pin/mute/archive trio) · History transcript rows (copy/download/delete trio) · .wp-mini.wp-thread-flag

The thread head and History rows render groups of icon-only buttons whose names live in title tooltips (and aria-labels). Tooltips are hover-only — keyboard and touch users never see them — and the icons read ambiguously: the archive glyph is a trash can one pixel-tongue away from delete, at the same visual weight as copy and download. A misfire here archives a conversation or deletes a note. Confirm dialogs exist for contact removal; these rows have none.

Fix One of: visible text labels on hover-reach (a truncating label like the island toggle already has), a confirm step for the destructive member only, or visually differentiated weight for the destructive action (the .wp-mini.wp-danger tint exists — use it on the archive/delete glyph).
Important · settings row renders incomplete state

The CRM row is the only service row without a status dot

internal/web/views/settings.templ:355 (crmDetail)

Every Settings service row pairs its state phrase with a glance dot — green (wp-service-on) or muted (wp-service-off). crmDetail emits only the wp-service-on arm, so when the CRM is unset, auth-failed or in setup, the row renders bare — verified in the captured Settings screenshot, where five rows carry dots and the CRM row does not. The row's four-state copy is deliberate; only the dot is missing.

Fix (one line) Add the off arm: templ.KV("wp-service-off", state != "connected").
Important · consistency

English mixes 12-hour and 24-hour clocks between panels

internal/web/views/helpers.go:168-197 (formatFor, formatClock, formatWhen, fullStamp)

In English, a message bubble says 1:45PM (Kitchen format), while a History row on the same screen says Nov 7, 00:45 (24-hour), and the hover stamp says Nov 7, 2026, 3:04PM — three conventions, two clock systems, one locale (verified in captured screenshots 04 and 09). German is consistently 24-hour everywhere, which makes the English page the odd one. Times are glue users read dozens of times a day; the mixed format reads as neglect every time.

Fix Pick one English convention — Kitchen (1:45PM) everywhere is the friendlier voice — and let formatWhen's English branch ride it.
Important · promise the UI cannot keep

"Prefill from AI draft" renders even when the server has no AI

History transcript rows · the same row prints "AI review not configured on this server."

A transcript row on a server without the agent seam shows the line "AI review not configured on this server." and, two inches below it, a Prefill from AI draft button. The panel contradicts itself: one element says the capability is absent, the next offers it. Pressing it on such a server fails after the fact. This is exactly the class the repo's own honest-UI doctrine (capability DECLARED, never discovered as a failed action) exists to prevent — the fax tab already models the fix.

Fix Gate the prefill button on the same view prop that gates the "not configured" line (the pattern VoicemailPanelProps.ASR / FaxCapability already established), so the afford exists only when the seam can answer.
Nice to have · WCAG 2.5.8 target size

Attachment-chip remove buttons are 18×18 px

app.css .wp-chip-x (width/height: 18px)

The composer's attachment chips carry an 18-pixel remove button — under the 24×24 WCAG 2.5.8 minimum. The coarse-pointer 44px bump covers .wp-mini but not this class; on a touchscreen, removing the wrong attachment is a thumb-slip away.

Fix Grow the hit area without growing the glyph: keep the 18px visual, add padding + negative margin (or a ::before hit-expander) to reach 24px.
Nice to have · empty-state voice depth

History's empty state is the terse sibling of Voicemail's

history.templ vs voicemail.templ empty states

Voicemail explains what, who and effect ("Voicemail lives on the PBX. Ask the operator to enable the phone API (phone_api_url); messages will appear here and in the phone panel."); History, same condition, answers "Needs the operator phone API (phone_api_url)." — a config-key verdict where the sibling panel teaches. Same server, same user, two levels of help.

Fix Let History's empty state borrow Voicemail's three-beat shape (what / who acts / what happens next). One sentence each.
Nice to have · type-scale hygiene

Fourteen distinct sizes below 1rem blur the hierarchy

app.css meta-text sizes (0.68em–0.95em, mixing em and rem)

Between the body size and the smallest badge, the stylesheet carries fourteen distinct font sizes (0.68, 0.72, 0.75, 0.78, 0.8, 0.82, 0.85, 0.86, 0.88, 0.9, 0.92, 0.95…). Neighbors like 0.72/0.75/0.78 are visually identical at 15px root — they cost consistency without buying hierarchy, and they make every new panel a fresh guess. The color tokens would never tolerate fourteen greens.

Fix Consolidate to a 3-step secondary scale (e.g. 0.8 / 0.875 / 0.95) as custom properties, and migrate opportunistically — new panels must pick from the scale, the corpus catches up as panels are touched.
Nice to have · token bypasses

Radii and spacing bypass the tokens the palette already has

app.css: 8px radii (.wp-nav-link, #lang, .audio-out select, .wp-typeahead li), untokenized paddings throughout

The system defines --radius-sm 6 / --radius 9 / --radius-lg 12, then a handful of rules hardcode 8px, and spacing values (22px, 24px 26px 26px, 10px 12px…) are freehand while the color vocabulary is strict. The result looks coherent — the eyeballing was done once, by hand — but nothing enforces it for the next contributor.

Fix Fold the 8px outliers into the existing scale (6 or 9 — pick per surface), and introduce 2–3 spacing tokens for the row and panel rhythms. No visual change required, only names.
Nice to have · rhetorical calibration

The uppercase micro-label is doing the work of seven

.wp-crm-key, .wp-settings-head, .wp-reports-head, .wp-day-head, .wp-unread-divider, .wp-transcripts h3, .status

One device — small tracked-out uppercase — labels the CRM facts, the Settings sections, the Reports sections, the day separators, the unread divider, the transcript section and the status pill. Individually each is right; together they dull each other, and the connection states ("RECONNECTING IN 2S (TRY 1)") shout in the same voice as the section headers whisper. The retry counter's engineer-speak ("TRY 1") also leaks telemetry into copy where "Reconnecting…" would carry the same truth more calmly.

Fix Reserve the uppercase voice for section headers (Reports, Settings, transcripts); drop it from the day divider (sentence case, it already has the hairline) and humanize the reconnecting pill copy.

02The fix queue, in order

Three tranches. The first is one token and a re-pinned screenshot run; the second is a handful of one-liners; the third is taste work the next panel touch should carry, never a dedicated refactor. 

/* Tranche 1 — the dark-theme ink flip (both mirrored token blocks) */
:root,
:root[data-theme="dark"] {
  --on-accent: #0b0d11; /* was #ffffff: 3.21:1 on --accent, 1.87:1 on hover */
  /* --accent stays #17a467; the lit key keeps a dark legend, like the
     hardware phones the island already imitates. */
}
  1. Tranche 1 — correctness (one sitting): the --on-accent flip in app.css + island/style.css; the CRM row's wp-service-off arm; re-run scripts/ui-capture.py and re-measure the five filled surfaces.
  2. Tranche 2 — one-liners (one review): meta theme-color + manifest onto the real palette; English clock unified on Kitchen time; gate Prefill from AI draft on its seam prop; chip-X hit area to 24px; History's empty state reworded.
  3. Tranche 3 — taste, carried by future work: icon-action labeling/confirmation pattern; type-scale consolidation; radius/spacing token adoption; uppercase-voice zoning; reconnect-pill copy.
Why this order Tranche 1 removes the only WCAG failure in the product and costs a token; everything else is consistency debt that compounds quietly but never burns.
