01What the scan found

The flake's webphone-module check was broken (every nix flake check failed)

Two stacked defects in the hsts-opt-in variant: the module list was double-wrapped (lib.evalModules {'{'} modules = moduleSet … {'}'} passes a set where a list is expected), and the base config merged extras with a shallow // that clobbered services.webphone. The HSTS option and its check had landed without a completed nix flake check run. Fixed: single evalModules call + lib.recursiveUpdate. Check now runs green.

treefmt/gofmt violation in internal/server/contract_test.go

A hand edit committed without gofmt failed the format check inside nix flake check and buildflow's nix-build step. Fixed with gofmt -w.

Everything else is clean, with proof

go test ./... green (all packages, plus a new black-box Ginkgo suite for the session contract); golangci-lint run → 0 issues; erraudit lint --type-aware / --no-suppress → 0 findings; art-dupl --type-aware -t 5 → "Found total 0 clone groups"; govulncheck → 0 vulnerabilities affecting code (4 in required modules, none called); scripts/webphone-smoke.py → 26/26 passed; buildflow (BUILDFLOW_NO_RESULT_CACHE=1) → no failed steps; the 9 "tools unavailable" are the documented not-applicable noise (AGENTS.md). vulnix-in-buildflow flags build-closure inputs (bison/gcc/coreutils) — never deployed; the repo's runtime-closure app (nix run .#vulnix, 8 derivations) is the scoped gate.
