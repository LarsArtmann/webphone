The 2026-09-19 review's headline holds: this is a model where the invalid states mostly cannot be constructed. All five aggregates carry branded nanoid identifiers with the Parse/Must split (client input 404s, database corruption panics); Extension and Phone are constructor-validated struct wrappers; inbound and outbound lifecycles are separate types, not nullable-flag minefields; and the provider-ref partial unique indexes still make replayed status webhooks unrepresentable at the storage layer. Since that review the model grew — Message.FailureKind / FailureDetail (send-failure train C), the CRM Match/Resolver types, retention's SweepResult/Counts, session sliding-TTL Lifetime — and every addition followed the established patterns.

What changed for the worse: nothing inside domain. What remains open lives exactly where the 09-19 review left it — at the operator-config boundary — plus one genuinely new finding: the gateway Receipt type is too thin to carry a fact the fax service needs, which forces an implementation type-assert that the architecture review also flags.

01Problem catalog

New · P5

Receipt cannot express how a gateway resolves — the type-assert is a symptom

internal/gateway/gateway.go — Receipt{ProviderRef string}; internal/fax/service.go:136

The fax service branches on which implementation it got (s.gateway.(*gateway.Loopback)) because the data it needs — "does this receipt already carry the final verdict, or do I wait for a status hook?" — has no home in the model. A second synchronous gateway (spooler, second provider) silently takes the wrong branch. This is the architecture review's carried finding #2, re-filed here because the honest fix is a model fix: the interface's return type is missing a field, and the assert is the caller reaching around the missing field.

Fix Give Receipt a closed two-value enum for resolution (see §03): the service switches on the contract; implementations declare what they are. The assert dies without touching either gateway implementation's shape.
Carried · P4

identities keys are Extensions that nothing validates

internal/config/config.go — Identities map[string]string

The own-number feed maps extension → DID, but the key is a raw string. The type's own doc comment carries the warning — "keys must be normalized extensions or lookups by the signed-in extension silently miss" — which is the definition of a fail-silent boundary: the process boots green on a typo, and the feature it broke is discovered by a human weeks later. Contrast the same package's timezone handling, where a typo fails the boot on purpose.

Fix Validate at Load(): every key through domain.ParseExtension, reject the boot naming the offending key. The wire shape stays map[string]string (koanf + the config-file contract are untouched); the guarantee moves from a comment to a check.
Carried since 09-19 · P4

SharedContact.Number is the one unbranded number

internal/domain/contact.go:22

Personal contacts store Phone (branded, validated); shared contacts store a raw string whose lowercase JSON form is the window.PBX_CONFIG wire contract. A malformed operator entry renders verbatim in the island's dial typeahead. The 09-19 review accepted this pending "a config-validation decision" — that decision is now overdue and has an obvious answer (same as finding #2: validate at load).

Fix ParsePhone on every shared-contact number in Load(), same home as finding #2 — one change, two reviews' items closed. The wire stays lowercase strings; only the boot-time guarantee changes.
Carried · P8

No schema version home yet

internal/store/db.go — CREATE TABLE IF NOT EXISTS only

Every schema statement today is idempotent-create; nothing alters an existing table, so no version marker is needed yet. The model should grow schema_version before the first altering migration arrives, not during it. (Same item, same status, in the architecture review.)

Accepted, re-confirmed

Two documented deviations stay

FaxJob.Error · session.Session.Password

FaxJob.Error remains a display-only reason string (structured error typing would buy a join table's complexity for zero behavior — 09-19 verdict re-read and re-accepted). Session.Password remains at rest by design: the row must carry the directory password the /phone-api proxy needs, the trade-off is documented at the package doc, and the value is swept on read/Create. Both carry doc comments stating the acceptance — the pattern to copy for future deviations.

02The vision

+
Every id is branded, every boundary validatesClient input meets Parse* (404/reject), database rows meet Must* (panic = corruption), config meets… validation too, once §08 step 2 lands — no fourth path.
+
Interfaces return facts, implementations stay anonymousNo caller of MessageGateway/FaxGateway ever learns which concrete type answered — after the Receipt fix removes the one exception.
+
Lifecycle states are types, not flagsInboundMessage/Message and InboundFax/FaxJob pairs keep "no status" and "status pending" unrepresentable-by-construction; OutboundStatus's zero value means not-applicable, documented.
+
Storage enforces what handlers merely re-checkPartial unique indexes on provider_ref make webhook replays unrepresentable; owner scoping lives in every query.
+
Wire contracts stay boringpbx CDR/voicemail field names mirror the upstream API exactly; SharedContact JSON tags are the PBX_CONFIG contract — types stay honest inside, payloads stay verbatim outside.
+
Zero values tell the truthRetentionDays 0 = keep forever, Gateway.Mode "" = loopback, Lifetime normalizes a missing cap — every zero value is a documented, safe default.

03Go data model — the three deltas

The redesign here is surgical: three type-level changes, nothing else. The existing model earns "keep" everywhere else. 

// gateway: resolution becomes a closed two-value enum on the receipt.
type Resolution string

const (
	ResolutionImmediate Resolution = "immediate" // verdict already final (loopback)
	ResolutionDeferred  Resolution = "deferred"   // status hook will speak next (webhook)
)

type Receipt struct {
	ProviderRef string
	Resolution  Resolution // gateway declares its own resolution shape
}
// config: the map's wire shape is untouched; the guarantee moves into Load().
func validateIdentities(m map[string]string) error {
	for key := range m {
		if _, err := domain.ParseExtension(key); err != nil {
			return errorfamily.WrapRejectionf(err, "config.identities",
				"identities key %q is not a dialable extension", key)
		}
	}
	return nil
}
// store: the version home, before the first altering migration needs it.
CREATE TABLE IF NOT EXISTS schema_version (version INTEGER NOT NULL)

07Anti-patterns to keep avoiding

Recorded for the next contributor (carried from 09-19, still true)

Do not add a new ID without its Brand struct. Do not "simplify" Must* back into handler paths — a panic per forged URL is a log-flooding vector. Do not widen predicates with unused parameters "for symmetry" (the ChannelOf lesson). Do not reach for a second user identity — the extension IS the identity. Do not add a nullable pointer where a separate inbound/outbound type says it better. And new: do not branch on a gateway's concrete type — if the interface's answer type lacks a fact, add the fact to the type.
