02Problem catalog

P1 · carried · High

push.Transport: a closed vocabulary living as raw map keys

internal/push/push.go — Fanout.senders map[string]Sender; Knows(transport string)

“ntfy” and “fcm” are a closed two-member vocabulary, but every consumer passes and compares raw strings; a typo compiles and fails at runtime as a silent no-match.

N1 · new · Medium-High

The thread view-model has a transitional home in the store package

internal/store/messages.go (ThreadSummary, ThreadFlag) + internal/readmodels/summary_view.go bridge

The engine view (readmodels.ThreadSummaryView, raw-string wire shape — correctly so, per the wire-DTO doctrine) re-parses at the gate into store.ThreadSummary — a type named for the retired SQL ladder, living in the store package, consumed by views and notifier. With the ladder frozen (sessions-only end state), the render shape’s home is transitional debt: two packages must both change for any thread-list field change.

N2 · new · Medium

ThreadFlag: a persistence-layer spelling of a domain concept, in the wrong layer

internal/store/messages.go (home) — spans 10 files: cqrs, readmodels, views, messaging, domain

The store comment says it outright: “ThreadFlag … is the persistence-layer spelling of the three bools on domain.Thread”. A cross-cutting closed vocabulary (pinned/archived/muted) whose home is a package being retired — and which domain.Thread duplicates as three bools. Two homes for one concept is the split-brain shape this series exists to kill.

P3 · carried · Medium

FaxJob.DocumentPath is a raw string beside a landed brand

internal/domain/fax.go:82 — site carries the 10-25 roadmap marker

domain.RelPath exists and is used elsewhere; the fax document path stays a plain string, so a display path and a blob path are interchangeable types at every consumer. The site honestly marks this as the recorded open item.

P4 · carried · Medium

Constructor string-trains at the wiring doors (asr, matrix)

asr.NewClient(baseURL, token, model string); matrix.New(homeserver, userID, token string)

Three-string parameter trains are position-capture traps (URL/token transposition compiles). Both sites carry parse-at-the-door rulings, so validation is not the gap — shape is. One wiring struct each kills the trap.

P5 · carried · Low

machineSurface: bool parameter not last

internal/server/internal_directory.go:40 — site carries the marker

Call-site readability only; the finding survives because the fix is a two-line signature reorder no train has picked up.

P6 · carried · Low, leaning decline

sso.Complete re-scatters the Challenge it minted

internal/sso/sso.go:158 — Complete(code, verifier, nonce string)

The 4th review proposed a Finish value object tying verifier+nonce to the minted Challenge so cross-challenge mixing is unrepresentable. The site ruling since landed (“OAuth2 protocol tokens, not domain concepts”) is defensible: these are foreign-protocol strings the cookie round-trip owns, and the empty checks reject the mixing cases. Recommendation: accept the site ruling, close the roadmap item unless a third state field appears (state, nonce, verifier + one more would tip the balance to the value object).

06Validation layer

The model’s validation posture is already the target: constructors parse at the door (ParseExtension sanitizes then rejects), engine wire shapes stay raw and re-parse at gates, boot typing is fail-closed (ConfigInvalidError), and every seam’s rejection vocabulary rides errorfamily codes with per-package family_test pins. The carried items add three parse-at-the-door doors (Transport, RelPath on fax, wiring structs) — each converts a runtime string-shape risk into a boot-time rejection, matching the established pattern rather than inventing one.

08Anti-patterns

Traps when adopting this model

Do not brand the engine view structs — they are the serialization wire; the doctrine is raw-at-rest, branded-at-gate. Do not move ThreadSummary into views to fix the arch-review P2; that P2 is about templ surfaces consuming infra packages — the fix is view-owned prop types for CDR/voicemail (pbx-client shapes), while the thread summary’s right home is readmodels (this review N1). Two moves, two different reasons. Do not re-litigate the baseline-ruled edge doors (ParseToken scan conversion, BearerGate pair) — 4th review ruling stands.
