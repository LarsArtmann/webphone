# sip.js "0.22" evaluation — 2026-09-18

**Verdict: nothing to bump to. Stay on 0.21.2.** The pinned version is
already the newest released sip.js, and the "0.22" this evaluation was
scoped for does not exist.

## Verified upstream state (2026-09-18)

## What the unreleased 0.21.3 delta contains

Exactly one merged PR (#1105): a 7-line change adding an `autoStop`
option to `SimpleUser` (control whether `stop()` runs on
`beforeunload`). Irrelevant here:

- The island drives the raw `UserAgent` API, not `SimpleUser`.
- We deliberately do not rely on library-level beforeunload behavior.

## Why staying on 0.21.2 is correct

1. **Zero benefit.** The only newer code upstream is the SimpleUser
   option above — none of it touches the transport, reconnect, DTMF, or
   REFER paths the island depends on.
2. **The reconnect hang is not fixed upstream.** The 0.x-series
   `userAgent.reconnect()` hang after transport loss (the reason the
   bounded 5s watchdog in the island's `connection.js` is load-bearing,
   see AGENTS.md) has no fix in any tag through 0.21.3. A bump would
   not remove the watchdog; it would just invalidate four years of
   battle-testing against FreeSWITCH.
3. **Bundle-contract cost.** Any repin re-runs `./update.sh` and
   requires the upstream browser E2E re-run (DOM + greppable-string
   contract). Paying that cost for a null-delta upgrade is negative
   value.

## Re-trigger conditions

Revisit only when one of these happens:

- Upstream (or a credible maintained fork) ships a release that fixes
  the `reconnect()` hang — that would let us simplify the watchdog and
  would be worth the E2E re-run.
- A security advisory lands against 0.21.x (none known as of this
  date).
- The island ever needs a capability added after 0.21.2 (none today:
  calls, transfer, DTMF, notifications, ICE diagnostics are all
  covered).
