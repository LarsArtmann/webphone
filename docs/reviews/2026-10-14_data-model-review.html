01Series cross-reference — follow-ups resolved

Resolved · Receipt.Resolution (09-30 finding, P5)

Resolved · schema_version (09-30 finding, P8) — exceeded

The store now owns schemaVersion 3 with an ordered migration chain: v1 recreates the historical shape (tolerant of legacy duplicate-column ALTERs), v2 adds thread flags + snippets, v3 adds call transcripts. The proposal asked for a version home "before the first ALTER"; the delivered design already survived two.

02Problem catalog

Eight new findings, graded by severity. They share one root cause: closed vocabularies and multi-field verdicts represented as bare strings — the exact gap between the model's two existing disciplines (IDs get brands + parsers; enums get a type name and nothing else).

High

FailureKind is a stringly vocabulary — and the retry rule lives in the view

internal/domain/message.go — Message.FailureKind string · internal/messaging/service.go · internal/web/views/messages.templ

The delivery-failure vocabulary — "", "transient", "rejected", "provider" — is documented in a field comment and enforced nowhere. It has TWO construction homes (failureKindOf maps a send error; DeliveryReceipt assigns the literal "provider") and its one business rule — only transient is retryable — is executed by the VIEW layer as a string comparison (msg.FailureKind == "transient" in messages.templ, which decides whether the Retry button renders). The domain vocabulary grew a second writer within a month of its birth; the rule that governs it drifted two layers away from the type that owns it.

Fix A closed FailureKind enum whose values ARE the stored strings (DB bytes stay identical), with IsRetryable() as the one home of the rule; the templ renders Retry iff msg.FailureKind.IsRetryable(). See §04 delta 1.
High

Direction × Status legality is cross-axis — and representable wrong

internal/domain/message.go — Message · internal/domain/fax.go — FaxJob

The lifecycle invariants are comments, not types: an inbound message's Status must be the zero value ("the only legal status for inbound"); "received" is an inbound-only fax status; queued/sending/transmitted are outbound-only. Yet Message{Direction: in, Status: sent} and FaxJob{Direction: in, Status: queued} both compile and both scan happily out of the database. The 09-30 vision line said "lifecycle states are types" — true at the gateway boundary (InboundMessage/OutboundMessage, the baselined split), still false at the aggregate the UI actually renders.

Fix Keep the flat row types (SQLite scan simplicity is a real constraint) but move legality to mint time: NewOutboundMessage / NewInboundMessage / NewOutboundFax / NewInboundFax constructors refuse illegal Direction×Status pairs, and the store's read path canonicalizes through enum parsers so a corrupt row panics like a corrupt ID does. See §04 delta 2.
Medium

Enum reads skip the corruption policy the IDs already obey

internal/store/messages.go — scanMessage, scanThreadSummary · internal/store/faxes.go — scanFax · internal/store/transcripts.go — scanTranscriptRow

Every ID read from a row goes through domain.Must* — a malformed id panics, and the panic is the honest crash for corruption. Every enum read from a row is an unchecked cast: domain.Direction(direction), domain.Channel(channel), domain.OutboundStatus(status), domain.FaxStatus(status). A corrupted or hand-edited row yields an out-of-vocabulary enum value that flows silently into views and comparisons — the one boundary where the model's own corruption doctrine is not applied. No ParseDirection/ParseChannel/ParseOutboundStatus/ParseFaxStatus exists anywhere in the repo.

Fix Parse-or-panic helpers beside the enum declarations, used by the scan functions — the enum twin of MustThreadID. Same policy, one new home per vocabulary.
Medium

Delivery verdicts travel as four loose parameters

internal/store/messages.go — UpdateOutboundStatus · internal/store/faxes.go — UpdateStatus

UpdateOutboundStatus(ctx, id, status, providerRef, failureKind, failureDetail) — three adjacent strings and an enum; every transposition compiles. The store's own doc comment encodes a cross-field invariant ("a delivered verdict CLEARS any earlier failure") that the signature cannot express and each caller re-implements. Faxes repeat the shape with (status, providerRef, errorText, pages). The existing nolint rulings correctly reject branding ProviderRef (webhook DTO + partial-index + golden-row ripple) — but a value object carries the verdict WITHOUT re-typing the ref.

Fix A domain.Delivery value (Status, ProviderRef, FailureKind, FailureDetail) whose constructor enforces the clear-on-delivered and failure-story-only-on-failed invariants; the store takes one Delivery. See §04 delta 1.
Medium

CallTranscript keeps Remote unbranded — with no ruling behind it

internal/domain/transcript.go — CallTranscriptSegment, CallTranscript

CallID's raw string is a documented, nolinted ruling (the island-owned SIP Call-ID, opaque passthrough, never joined to CDR rows — the 09-18 pbx-UUID class). Remote has no such rationale: it is a phone number, every sibling type (Message.Remote, FaxJob.Remote, Thread.Remote) brands it as domain.Phone, and the transcripts table is the one place a remote number travels as an unchecked string from the island's POST through the store into History renders. Two spellings of one number now diverge between the Messages tab and the History tab.

Fix ParsePhone at the transcript API boundary (the handler that accepts island posts), store and render domain.Phone. CallID stays raw — that ruling stands.
Medium

The session token is the one credential-shaped string with no type

internal/session/service.go — Store seam · internal/sipcred/sipcred.go — Derive

Store.Create returns a bare string; Get/Renew/Delete/ActiveTokens take one; sipcred.Derive takes (secret, sessionToken string); the cookie handlers pass it around as a string. The token is 256 bits of entropy that mints SIP REGISTER credentials and revokes them — the highest-stakes string in the process — and the compiler will happily accept a provider ref, a CSRF token, or a filename in its place. Every other high-stakes identifier in this repo already wears a brand.

Fix A session.Token defined type minted by makeSession (the one home) and threaded through the Store seam and sipcred.Derive. Zero wire change — the cookie still carries the raw form.
Medium

Blob paths are three raw strings for one concept

internal/blob/store.go — Save/Open/Abs/Remove · domain.Attachment.Path · domain.FaxJob.DocumentPath · gateway.OutboundFax.PDFPath

The "path relative to the data dir" contract lives in doc comments. blob.Open refuses escapes at runtime — which catches hostile HTTP input but not a confused caller storing an absolute path into Attachment.Path (the sweep and the download handler would then resolve it against the wrong root or serve it directly). The same value crosses three spellings: store-relative (persisted), absolute (gateway upload), and raw reader paths.

Fix A domain.RelPath defined type: Save returns it, Open/Abs/Remove take it, the stores scan into it. The runtime escape check STAYS for the HTTP boundary; the type kills the confused-caller class. The type home is domain — settled by the arch test (TestDomainImportsNothingInternal): domain may not import blob, so blob converts at its edge. Corrected 2026-10-14: this callout originally claimed the type could live in blob and be referenced from domain — that edge is exactly what the arch test forbids (see the companion status report, defect d1).
Low

RetentionDays rejects nothing — negative silently means forever

internal/config/config.go — RetentionDays · internal/app/app.go — retention.Start wiring

Zero is documented as "keep everything forever" and the sweeper honors it by not starting. A negative value takes the same silent path (non-positive window → disabled) without the documentation or the intent — a typo'd "-30" boots green and keeps every message forever, the exact fail-silent shape the 09-30 review deleted from identities.

Fix One validate() clause: negative RetentionDays is a Rejection naming the value and the fix ("use 0 to keep everything").
Low

Gateway dispatch fails OPEN on an unknown mode

internal/gateway/gateway.go — NewMessageGateway, NewFaxGateway

Both pickers switch on GatewayMode with default: return &Loopback{…}. Config.validate makes an unknown mode unreachable at boot — but a second caller, a test fixture, or a future mode enum value falls into a default that FAKES SUCCESSFUL SENDS. In a send path, fail-open is the wrong failure shape even when guarded upstream; loopback is a deployment decision, not a fallback.

Fix Exhaustive switch (loopback; webhook; default panics with the mode value). Post-validation unreachable code should fail loudly, not impersonate the dev gateway.
Low

Smaller vocabulary leaks

internal/config/config.go — ASR.Provider · internal/server/sse.go — ExtensionHubs maps

ASR.Provider carries "openai"/"google"/"" as magic strings checked by a validate() switch and a Google() method — a typed enum with Google() replaced by a comparison would close it. ExtensionHubs keys its hubs, langs and seen maps by extension.String() — domain.Extension is a comparable struct, so map[domain.Extension]X works with zero plumbing and keeps the brand to the map boundary (config-file maps stay strings: koanf + JSON are the contract). Neither leaks user-visible behavior today; both are free at the next touch.

Strengths — the model to preserve

+
Ten branded ID families with the Parse/Must split Thread/Message/Attachment/Fax/Contact/Snippet in domain, ContactRef in crm, Tag/DocType/Field in paperless (int-branded). Client input meets Parse* (404/reject), rows meet Must* (panic = corruption). No fourth path anywhere.
+
Extension and Phone are constructor-validated wrappers over ONE sanitizer sanitizeDialable is the single alphabet home, pinned by a Go test AND the served-asset table — the same rule the island's dial field applies. History rows and threads key identically by construction.
+
Storage makes webhook replays unrepresentable Partial unique indexes on provider_ref (messages + fax_jobs, empty refs exempt) — a replayed verdict can never double-apply. Owner scoping lives in every store query; attachments stream only through session-gated joins.
+
Caps enforced in one INSERT statement ContactsMaxPerExtension (500) and SnippetsMaxPerExtension (100) live in the INSERT's WHERE clause — the cap holds under concurrent saves with no read-then-write race. Transcripts add a scalar-bounded trim (per-owner 5000, per-call 1500) that cannot materialize a keep-list.
+
Versioned, transactional migrations with one shape-history Fresh and legacy databases walk the same chain; a failed step aborts at its version and a retry resumes there. The 09-30 "version home before the first ALTER" debt is paid with interest.
+
Fail-closed config with named offenders Every half-configuration (both-or-neither seams, passkey half-wiring, token-without-URL, dead TURN secret) is a rejected boot citing the exact key and the fix. Identities and shared contacts joined this discipline in this window.
+
Boundary shapes stay separate on purpose AttachmentContent (raw bytes) → Attachment (stored) → OutboundAttachment (wire ref); domain.SharedContact / vcard.Card / apiSharedContact; CDR/voicemail DTOs mirror the upstream API verbatim. The baselined rulings in docs/dedup-registry.md protect each — this review confirms all of them are still the right calls.

03The vision

+
Every closed set is a type The failure vocabulary, the ASR provider kind, the gateway mode dispatch — no bare string carries a domain rule. The enum values ARE the stored bytes, so storage never migrates.
+
Every lifecycle is legal at mint time Constructors own the Direction × Status pairing; an inbound-with-status message or an inbound-queued fax cannot be built, and corrupt rows panic like corrupt ids.
+
Verdicts travel as values Status, provider ref and failure story move as one Delivery — no transposable ladders, no cross-field invariants re-implemented per caller.
+
High-stakes strings wear their intent The session token and the blob-relative path are branded; the compiler, not a code reviewer, catches the confused caller.
+
Zero values stay honest 0 retention = documented forever; a negative retention is a rejected boot; an unknown gateway mode panics instead of impersonating the dev loopback.
+
The boundary doors stay exactly three Client input meets Parse* (404), rows meet Must*/parse (panic = corruption), config meets validate (rejected boot naming the key) — and enums finally walk through the same doors as ids.

04Go data model — the deltas

The redesign is surgical: six type-level changes, nothing else. The existing model earns "keep" everywhere else — every change below reuses a discipline the codebase already applies to IDs.

Delta 1 — the failure vocabulary becomes a type; verdicts become a value

// domain/message.go — the enum values ARE the stored strings:
// no migration, no data rewrite. The rule gets one home.
type FailureKind string

const (
    FailureNone      FailureKind = ""          // no failure (default)
    FailureTransient FailureKind = "transient" // transport/5xx: retryable
    FailureRejected  FailureKind = "rejected"  // our request: not retryable
    FailureProvider  FailureKind = "provider"  // async webhook verdict
)

// IsRetryable is THE home of the retry rule — the view asks, never parses.
func (k FailureKind) IsRetryable() bool { return k == FailureTransient }

// domain/message.go — one value carries the whole verdict;
// the cross-field invariants live in the constructor.
type Delivery struct {
    status        OutboundStatus
    providerRef   string // stays raw: the nolint rulings stand (DTO/index/golden ripple)
    failureKind   FailureKind
    failureDetail string
}

func NewDelivery(status OutboundStatus, providerRef, failureDetail string) (Delivery, error) {
    switch status {
    case StatusSent, StatusDelivered:
        return Delivery{status, providerRef, FailureNone, ""}, nil // delivered CLEARS failure — here, not per caller
    case StatusFailed:
        return Delivery{status, providerRef, FailureProvider, failureDetail}, nil
    default:
        return Delivery{}, errorfamily.NewRejection("domain.delivery", "not a delivery verdict")
    }
}

Store signature collapses from six parameters to three (UpdateOutboundStatus(ctx, id, d domain.Delivery)); messaging's two construction sites (failureKindOf and the literal "provider") collapse into NewDelivery; the templ asks msg.FailureKind.IsRetryable(). The DB bytes, the export wire and the golden-pinned rows do not move.

Delta 2 — lifecycle legality at mint time; corruption panics at read time

// domain/message.go — constructors make the illegal pair unbuildable.
func NewOutboundMessage(owner Extension, remote Phone, body string, ch Channel, now time.Time) Message {
    return Message{Owner: owner, Remote: remote, Body: body, Channel: ch,
        Direction: DirectionOutbound, Status: StatusQueued, CreatedAt: now}
}

func NewInboundMessage(owner Extension, remote Phone, body string, ch Channel, at time.Time) Message {
    return Message{Owner: owner, Remote: remote, Body: body, Channel: ch,
        Direction: DirectionInbound, CreatedAt: at} // Status stays zero — the only legal inbound status
}

// domain — parse-or-panic twins of the Must* id family, one per vocabulary.
func parseDirection(s string) Direction { // same contract as MustThreadID:
    switch Direction(s) {
    case DirectionInbound, DirectionOutbound:
        return Direction(s)
    default:
        panic("corrupt row: direction " + s) // corruption is the only source
    }
}

The scan functions switch from unchecked casts to the parsers; fax gets NewOutboundFax/NewInboundFax and a parseFaxStatus the same way. Flat row types stay — the union lives at the gateway boundary where the baselined split already put it.

The runtime escape check STAYS: it guards the HTTP boundary where the value is still attacker-controlled text.

08Anti-patterns to keep avoiding

Carried from 09-19 / 09-30 (still true)

No new ID without its Brand struct. No "simplifying" Must* back into handler paths. No unused parameters for symmetry (the ChannelOf lesson). No second user identity — the extension IS the identity. No nullable pointer where a separate type says it better. No branching on a gateway's concrete type (fixed — keep it fixed).

New — recorded this review

No "temporary" stringly vocabulary: FailureKind gained its second writer (the literal "provider" in DeliveryReceipt) within a month — every unchecked vocabulary grows writers faster than types. No fail-open default in send paths: falling back to a dev gateway that fakes success is the worst reachable failure shape, even behind boot validation. No negative-tolerant "disabled" ints where 0 already means disabled: two values meaning "off" is one undocumented value waiting to be a typo. No unruled exceptions to a naming/branding discipline: CallID's raw string carries a written ruling; Remote's raw string carried nothing — that asymmetry was the smell.

09Migration roadmap

1

domain.FailureKind + Delivery value object

The enum (values = stored strings), IsRetryable(), NewDelivery; collapse UpdateOutboundStatus's signature, both messaging construction sites, and the templ retry check. Run the session-behavior suite's messaging arm + store tests + a nix fmt (templ changed). M effort — closes findings 1 and 4, the two highest-value items.

2

Must* enum parsers at every row read

MustDirection/MustChannel/MustOutboundStatus/MustFaxStatus beside their declarations; scanMessage, scanThreadSummary, scanFax, scanTranscriptRow switch over. S effort — closes finding 3.

3

Lifecycle constructors for Message and FaxJob

New{In,Out}boundMessage / New{In,Out}boundFax mint every aggregate (services and tests switch over; struct literals remain legal for scan-adjacent code but the service paths all mint). S–M effort — closes finding 2.

4

config + dispatch hardening

Reject negative RetentionDays in validate() (with a config test asserting the message); exhaustive gateway dispatch with a panicking default. S effort — closes findings 8 and 9.

5

session.Token through the Store seam

Defined type minted in makeSession; Store interface, both backends, cookie handlers and sipcred.Derive convert at the edge. Carries an auth: commit prefix and the session-behavior suite per the auth-regression convention. S effort — closes finding 6.

6

domain.RelPath (layering settled by the arch test)

Defined type in domain — TestDomainImportsNothingInternal forbids the domain→blob edge, so the type cannot live in blob; blob converts at its edge (Save/Open/Abs/Remove), the stores scan into it, and the runtime escape check stays for the HTTP boundary. M effort — closes finding 7.

7
