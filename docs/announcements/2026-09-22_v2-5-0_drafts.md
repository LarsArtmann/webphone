## Draft B — v2.5.0 headline post

**webphone v2.5.0 — errors that tell the truth, recovery that does not
wait**

webphone is a single-binary Go unified-communications web app: the
proven SIP.js call island plus server-rendered Messages, Fax,
Voicemail, History, Contacts and Settings tabs on one page.

The theme of this train: when something fails, the user sees WHY, and
when something breaks silently, the system heals itself.

- **Provider answers, not "unreachable"**: sending an SMS your provider
  structurally refuses (content policy, invalid destination — or the
  classic "source and destination cannot be the same number") now shows
  the provider's own reason in the panel. Message and fax lanes share
  one typed failure ladder: validation mistakes stay 422, provider
  answers become 502 with the real reason, outages stay honest
  transport errors.
- **Self-healing SIP registration**: a registration lost AFTER it was
  established (server-side contact drop, rejected re-REGISTER after a
  transport blip) used to wedge the phone silently until reload. The
  watchdog now rebuilds the whole agent, a 15-second cycle deadline
  catches wedged reconnects, and — because sip.js fires no state event
  when a Registerer re-registers without leaving `Registered` — the
  status pill is set explicitly on recovery. Root-caused with a
  5-run E2E campaign; the fix is pinned by nine stub scenarios.
- **Sign in once per device**: sessions survive server restarts
  (SQLite store), resume at page load without a login click, and slide
  while in use (7-day idle, 30-day absolute cap — a stolen cookie dies
  at the cap even under constant use).
- **Operator story**: daily backup timer with a restore DRILL as a
  flake check, dedicated `/healthz` `/livez` `/startupz` vhost
  locations for fleet scrapers, typed `csrf.*` and `serverTiming`
  module options, one bundled htmx extension, and a styled, translated
  404 that keeps the app shell.
