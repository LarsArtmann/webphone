## Draft B — v2.7.0 headline post

**webphone v2.7.0 — doomed sends fail fast, and the UI library
adoption is no longer a bet**

webphone is a single-binary Go unified-communications web app: the
proven SIP.js call island plus server-rendered Messages, Fax,
Voicemail, History, Contacts and Settings tabs on one page.

The theme of this train: adopt the library stack where it is PROVEN,
and refuse work that cannot succeed — before doing it.

- **Self-sends fail before the roundtrip** (send-failure train C): a
  message or fax addressed to your own number used to burn a provider
  call just to be told "source and destination cannot be the same
  number" (Telnyx 40310). It now fails locally in the same breath as
  the send click — 422 with the reason, zero provider traffic — and
  the failed row still lands in the thread as evidence, exactly as a
  provider refusal would have left it. Both halves of the tradeoff,
  no tradeoff taken.
- **templ-components EmptyState, with receipts**: six true empty
  states now render through the library, served by a permanent
  14.5KB scoped Tailwind v4 build. Coexistence with the hand-rolled
  token CSS was not assumed — a Chromium A/B spike measured all
  existing surfaces byte-identical across 14 computed properties
  (Tailwind v4 emits `@layer` only; unlayered CSS wins every
  collision). The rejected candidates (RelativeTime, CountBadge,
  errorpage) each carry a written rationale.
- **Hardening**: upload bodies bounded at a 61MB envelope before
  multipart parsing (a plain 400 instead of unbounded streaming),
  500 responses redacted to the family default while operators keep
  the full error in the log, Retry-After hints on fail-closed
  surfaces, and the middleware chain pinned by httputil's 19-spec
  conformance suite.
- **Dependency sweep**: cqrs-htmx v4.12.0, httputil v1.3.0,
  go-error-family v0.10.2, go-sse v0.6.1 — HubFanOut benchmark
  re-run, no regression.

Browser E2E green; aarch64 verified by ELF bytes.

https://github.com/LarsArtmann/webphone/releases/tag/v2.7.0
