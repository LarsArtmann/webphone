404s, /health, and an unused appkit

Three questions, one plan: every error surface answers with the app's own chrome, the go-health dashboard becomes reachable at pbx.artmann.tech, and go-appkit gets a verdict instead of silence.

Blocker: /health exposure ruling

The work splits into three seams. 404 completeness lives entirely in webphone and is the cheapest customer-visible win. /health needs a decision about who may see it, then two small config edits in two other repos. go-appkit is an audit that ends in a written verdict, because the library is currently not a dependency at all.

Findings (evidence first)

go-appkit: 0% adopted, by prior ruling

github.com/larsartmann/go-appkit appears in neither go.mod nor any Nix file in this repo. The 2026-09-24 stack deep dive recorded “go-appkit and go-cqrs-lite: zero usage” and ruled it correct to leave alone. go-cqrs-lite has since been adopted (metaengine), so that ruling is stale on one half and silent on the other. The untouched module with a live gap is errorpages: pretty 404/405 plus a classified JSON contract, which is exactly the surface audited below.

We do have a 404 page, but only sometimes

handlers.notFoundPage renders the full shell around views.ErrorPanel and answers 404 with a 12,481-byte styled body for /nope. The same probe shows bare stdlib text (19 bytes, text/plain) for /health, /health/, and /assets/nope.js. Roughly 45 http.NotFound call sites answer before any shared surface decision, and 405 has no styled path at all. Measured on the local build at 2026-10-23 14:19.

/health is absent for two independent reasons

First, dashboard.enable defaults to false by deliberate ruling (T11, 2026-10-01): the dashboard is an unauthenticated operator surface that would duplicate /operator/. Second, even enabled it would be reachable but unfenced: the unbuffered /health/* proxy exists only in webphone's Caddy vhost generator, and the stack force-disables Caddy (caddy.enable = lib.mkForce false) in favour of its nginx vhost, which has locations for /, /events, = /metrics, /operator/, and no /health. Verified by reading modules/telephony/web.nix and running the binary with WEBPHONE_DASHBOARD__ENABLE=true: /health returns 50,879 bytes of HTML and the probe aliases return JSON.

Errata (what prior plans said, and what changed)

  • 2026-09-24 deep dive, go-appkit zero usage: still true, but it was a usage observation, not a capability verdict. This plan closes it with a per-module ruling.
  • 2026-10-01 T11, /health dashboard spike, verdict default-off: unchanged as a security default. What changes is that the operator realm now exists (Pocket ID pbx-operator forward-auth), so the “revisit only behind the operator realm” condition is satisfiable.
  • In-flight, not ours: internal/sso/, a go-oidc + oauth2 SSO seam, is uncommitted in the working tree from another session. Nothing here depends on it; the /health fence rides the stack's nginx forward-auth, which is already live.
