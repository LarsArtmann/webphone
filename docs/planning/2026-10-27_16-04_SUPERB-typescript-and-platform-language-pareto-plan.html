TypeScript, or Go→JavaScript, or Kotlin Multiplatform?

Three language questions arrived in one breath. Two of them are not migrations — they are rewrites of the operating premise. The third is real, and it is the cheapest type-safety win this repo can buy: type-check the island with TypeScript's own checker, emit nothing.

Rule from the planning discipline: a plan that re-dispatches decided work is worse than no plan. Four prior rulings bind this one.

  • Kotlin Multiplatform was already evaluated and rejected — docs/planning/2026-10-23_16-13_native-app-platform-decision.md, comparison table row "Kotlin Multiplatform (Compose Android + desktop Linux)": "Rejected: pays full-native cost AND lands the call engine on its least mature platform." The Linux leg's WebRTC options are named there (webrtc-kmp has no desktop target; Piasy kmp-webrtc is 2025-new; webrtc-java is the fallback). Option D would re-litigate it without new evidence, so this plan does not. Option E is the one variant that decision never priced.
  • Flutter is a standing hard no (owner ruling 2026-10-23, recorded in AGENTS.md § "Owner decisions (2026-10-23)"): closed for ANY path, Android or Linux, not subject to cost/benefit re-litigation. Not re-proposed here.

04Why B is not a downgrade

checkJs runs the same checker

TypeScript type-checks JavaScript. With allowJs + checkJs (or per-file // @ts-check) and the same strict flag set, tsc infers the same types from the same code and reports the same errors — the annotation carrier differs (JSDoc @param/@returns/@typedef versus inline syntax), not the analysis. What A adds over B is syntax ergonomics and TS-only constructs (enums, namespaces); what A removes is the property this repo is built on: the file you edit is the byte you serve.

Three concrete wins that land on day one of the gate, before any annotation marathon:

  • Config drift dies. window.PBX_CONFIG gets one declared shape; a server-side key rename in /config.js becomes a type error in the island instead of a silent undefined at runtime.
  • The SIP surface becomes checkable. A hand-written types/sip.d.ts pinned to the vendored 0.21.2 enumerates the calls the island actually makes — the 0.x upgrade class that the watchdog exists for.
  • Property/arity typos die in the 1,296-LOC calls.js and the 1,976-LOC shell.js, which the current gates cannot see: oxlint runs with every category off except no-undef, and no-undef says nothing about entry.holdPendng.

The exit is cheap and pre-paid: JSDoc annotations carry the exact type information a later .ts codemod needs, so A remains available if the named triggers fire.

05Pareto tiers

1% of effort → 51% of result

Teaching the gate to breathe

tsconfig.json + types/globals.d.ts + types/sip.d.ts + the island-typecheck nix check + two leaf modules annotated. Nothing else works until this exists, and once it exists every later file is a 15-minute self-contained unit. ~3–4 h.

4% → 64%

The call path

session.js → ice.js → pcsetup.js → connection.js → calls.js. This is where the incident classes live (hold state machine, registration watchdog, invite queue). If only five files ever get annotated, let it be these. ~6–8 h.

20% → 80%

Everything servable

Surfaces (panels, transcribe, typeahead, main, state), shell.js, the standalone page entries, then the 8,050-LOC test suite, then the checkJs: true flip that retires the per-file pragma. ~10–14 h, parallelizable.

What the tiers deliberately do NOT contain

No bundler, no npm dependency, no framework, no .ts file, no markup change, no stack E2E re-run. If a step needs any of those, it belongs to a different train and a different approval.

08Rejected paths, with evidence

C · Go server → JavaScript — reject by category, not by estimate

This is not a migration plan that lost a ranking; it is a proposal that removes the product's delivery mechanism. A Node port would have to reproduce, at minimum: the embed.FS single binary that the NixOS module starts as Type=simple (no Node runtime exists on that host today); modernc sqlite under /var/lib/webphone with its versioned migration ladder; the samber/do composition root with named critical services and go-health probes behind /healthz; the usermgmt/cqrs-htmx identity layer with WebAuthn and the durable auth-audit journal; the generated /openapi.json + docs/contracts/asyncapi.yaml; the errorfamily code registry with its freshness test; the 32-package DAG with its arch tests; every nix check (vendorHash, treefmt, island-lint, VM backup drill, vulnix triage); and it would still have to satisfy the stack's nixosModules.default option surface unchanged, or the consuming stack stops evaluating.

Effort: months. Benefit: none — the browser already runs the only JS that matters, and it ships inside the Go binary. Cost of adopting it: a second toolchain, a second lockfile, and an npm supply chain in the runtime path of a telephony product. The honest framing: if the goal is "less Go", the correct answer is a narrower surface, and this repo has already spent three series deciding which surfaces deserve splitting (the ratified answer: none; reopen trigger = a second Go consumer).

D · Full Kotlin Multiplatform — reject, prior adjudication stands

Already ruled on 2026-10-23 with the same evidence this plan would produce: Compose Desktop is production-ready, the native Linux WebRTC audio path is not (webrtc-kmp has no desktop target; Piasy kmp-webrtc is a 9-star 2025 newcomer; webrtc-java is the fallback). Calls are the product, so the ranking axis is the call path — and KMP puts it on the weakest leg while charging the full-native price (~0% reuse: every tab needs new JSON APIs, because today the surfaces are HTML fragments + SSE partials).

The web leg deserves a separate word because it is the newest temptation: a Kotlin/Wasm target would replace 7,280 LOC of proven, byte-served island against SIP.js 0.21.2, the dtmf-relay equals-form quirk, the morph-swap partial model, the CSP-with-no-inline-scripts posture and the three-gate served-byte contract — with a Compose-for-Web UI and a JS interop layer for sip.js. That is a rewrite of the product's frontend to gain a shared language, on the one platform where the current implementation is strongest.

A · Island → .ts with emit — defer, do not forget

The blockers are structural, not aesthetic: //go:embed all:island plus fs.Glob(embedded, "island/app/*.js") means the served tree is also the source tree; the import-closure test parses those sources; prettier owns their formatting; and three pin sites grep the bytes that ship. A generated tree is workable (templ does exactly this for *_templ.go) but it buys ergonomics the JSDoc path already delivers, and it costs a drift gate plus a codegen step in every contributor loop and in the daemon-commit story.

Deferral is honest only with triggers, so: (1) a browser-side npm dependency becomes justified (bundler arrives anyway); (2) JSDoc annotation overhead crosses ~1 line of JSDoc per 3 lines of code in a majority of files; (3) the island adopts a component framework. Absent one of those, B wins on every axis that is not syntax.

11Acceptance criteria for the whole train

  • git diff after T01–T06 touches only tsconfig.json, types/, nix/, docs and one test file — no island module content changes.
  • nix build .#checks.x86_64-linux.island-typecheck is green and network-free.
  • The served-byte pin sites are untouched and their suites stay green (Go tests, smoke script). The stack browser E2E is NOT owed, because no markup and no served asset changed.
  • Every opted-in file: 0 errors under strict, no bare any escape in new annotations, no @ts-ignore without a reason comment.
  • T06's pin fails if a pragma is removed or an unreasoned ignore is added.
  • Formatter ownership is split, not single. prettier (treefmt) never sees tsconfig.json or types/*.d.ts — nix/treefmt.nix's prettier includes match neither path. Those files are oxfmt/BuildFlow-owned (only island/**, shell.js, vendor/** and *_templ.go are excluded from BuildFlow). The criterion is therefore buildflow format-clean for the new files and nix fmt-clean for the island files the campaign touches. Erratum 2026-10-27: this bullet previously said "nix fmt clean" for everything, which cannot pass as written.

12Non-goals

  • No bundler, no minification, no npm dependency for the island.
  • No .ts file in stage 1 (that is candidate A, deferred).
  • No rewrite of src/ in webphone-android; T26 moves files and adds a plugin, nothing more.
  • No second KMP target, no Compose Desktop, no Kotlin/Wasm.
  • No Go-language change of any kind. No server-side refactor rides this train.
  • No behavior change: annotations only, or the change moves to its own commit with its own test.
