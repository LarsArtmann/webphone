Documented decision to amend

Thesis. The documented rejection of the setup bundle (split-brain identity) concerned its identity surfaces — the event-sourced usermgmt.Service, /auth/*, login page. That substance stays rejected. What webphone adopts is the runtime shell: the serve/drain/close lifecycle (RunHandler), the one-surface readiness composition (HealthPath + HealthChecks), opt-in LivePath, and the machine-endpoint mounts — composed behind webphone's existing, httpspec-pinned middleware chain via ExtraMiddleware + DisableSecurityMiddleware.

Decision conflict — must be ratified, not silently reversed

AGENTS.md, docs/lessons.md:21, and docs/DOMAIN_LANGUAGE.md:28 all pin the rejection. T01 writes a scope-limited amendment: identity surfaces stay rejected; shell surfaces are adopted after the upstream seams land. History docs stay untouched as provenance.

Two upstream gaps block adoption today

1) No Config.DisableAuth — /auth/* is built and mounted unconditionally (setup.go:68, mount.go:45), which would expose open registration into an in-memory second user database. 2) New() always constructs or adopts a usermgmt.Service (setup.go:38-48) — the service is the bundle's spine (svc.Journal()/EventBus()). Both need an upstream, test-pinned seam before webphone can compose the shell split-brain-free.

Why the shell is worth it

webphone already rides the same root-library primitives (cqrshtmx.ReadinessHandler + NamedCheck power /healthz today; server.go:270-274). Adopting setup deletes the hand-rolled main.go serve/shutdown block for the tested RunHandler (SSE-safe timeouts, 30 s shutdown budget, exactly-once Close), moves probe mounting behind one composition root, and — the strategic prize — makes webphone the reference identity-external consumer that hardens setup for a whole class of apps.

02Decision

Adopted

Mode S — runtime shell, identity untouched

upstream-first: DisableAuth + service-optional land in cqrs-htmx first

webphone composes setup.New with DisableAdmin + DisableDashboard + DisableLogin + DisableAuth (new) + shell mode (new), DisableSecurityMiddleware, RequestLogging=nil, ExtraMiddleware = the exact five-layer httpspec-pinned chain (ContextEnrichment → RequestLoggingSlog → ServerTiming → SecurityHeaders → Recovery), HealthPath=/healthz with HealthChecks=[sqlite, blob-dir @2s], LivePath=/livez. /startupz, /version, /metrics, /events stay webphone-mounted (no upstream equivalent / wire contracts pinned by stack + smoke).

Rejected

R1 — usermgmt as the identity (full reversal)

docs/lessons.md:21 · AGENTS.md

Sessions must carry the PBX directory password (the /phone-api proxy and GET /api/session's SIP-credential resume depend on it); usermgmt sessions cannot. Bridging would need a side credential table = two session truths. The original rejection stands unchanged.

Rejected

R2 — adopt as-is, dormant service, /auth mounted

mount.go:45

An always-mounted /auth/* writes into an in-memory second user database with open registration — attack surface plus the split brain the rejection named. Non-negotiable blocker; this is why T03 exists.

Fallback

R3 — cherry-pick into the root library instead

fallback if T12 size gate fails

If the footprint verdict is no-go and the owner declines a split submodule, the shell value (lifecycle, probe composition) gets promoted into cqrs-htmx root instead and setup stays rejected. Documented, not planned.
