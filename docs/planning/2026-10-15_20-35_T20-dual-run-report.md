## Findings (the port cost the byte-compare hides)

The fixture set (ordering, pinned-first, archived exclusion, unread counts,
same-second rowid tie-break, has-attachment flag, LIKE search incl. an
escaped `%` needle and ASCII case-insensitivity) reaches byte parity — but
only because the harness hand-built everything the SQL gets for free:

1. **Last message = a hand fold.** The correlated subquery
   (`ORDER BY created_at DESC, rowid DESC LIMIT 1`) becomes an update fold
   carrying prev-state comparison (`dualMessageAppended` in
   `internal/store/threadsdual_test.go`). Correct, but every consumer
   re-derives it.
2. **Compound sort does NOT push down.** `ORDER BY pinned DESC,
   last_activity_at DESC` has no engine equivalent on the sqlite engine:
   `WithSortColumns` documents that pushdown engines apply only the FIRST
   column (metaengine v4.19.0, scan_options.go:71). The read model must
   `WithLimit(0)`-scan and re-sort in Go (`sortDual`) — losing the reason a
   pushdown existed.
3. **Search = a hand-rolled LIKE.** The escaped-LIKE + `EXISTS` body search
   re-implements as a Go escape-walking matcher (`likeMatch`); ASCII
   case-insensitivity is mirrored by hand. The engine's full-text scan
   pattern is a different shape (not a LIKE port).
4. **Row state must become facts.** Threads/messages are external-fact SQL
   rows (N2: Telnyx is the system of record); feeding the engine means
   minting shadow events per row write — a second write path riding every
   ingest, or a tailing pump with its own lag/failure modes.
