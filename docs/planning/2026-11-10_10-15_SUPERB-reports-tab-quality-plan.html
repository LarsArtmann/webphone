The Reports tab: making the numbers tell the truth

The live panel folds 73 calls into a page whose every temporal answer reads as a fake zero, because the CDR date parser rejects 100% of the records. Five verified work items, about five and a quarter hours, turn it into the report its subtitle promises.

00Verdict

The projection’s arithmetic is sound and its honesty doctrine is right: unparsable records are counted, never dropped. What makes the current page trash is everything around that core. The ingest contract is broken at the source (FreeSWITCH writes start_stamp with seconds; the parser accepts none), so every “when” answer dies — and the view renders the death as “This week — 0 calls”, an empty “By day” heading, and a footnote at the very bottom that quietly explains both. On top of that, the “who” ladder ranks raw CDR strings (pifo42h1) and 49 of 73 outgoing calls that never connected are invisible.

The bottom line C1 is one line — startLayout gains the seconds it never had — plus a fixture with the real format. It alone returns This-week, By-day and Hours. Everything else is honesty (C2), the who (C3), the outcome (C4), and shipment quality (C5). Sequence: 1% first, then 4%, then the 20%.

◆What is already excellent

+
Honest-degradation doctrine Report.Undated counts unparsable rows instead of dropping them — totals stayed complete at 73 calls even in the degenerate state. The floor this plan builds on.
+
Pure projection The same records always fold to the same numbers; no storage, no clock of its own. Reproducibility is the tab’s whole acceptance criterion and it holds.
+
The display budget already exists TopContactRows caps name resolution to exactly the rows a reader sees — the seam C3 extends was designed for it.
+
One vocabulary with History Answered/Missed/Inbound/Outbound mean the same thing in both tabs, so they can never disagree about the same call.

01Findings

Blocking · root cause PROVEN at source

F1 — The wire format carries seconds; the parser rejects them

internal/reports/reports.go:27 (startLayout) · FreeSWITCH switch_channel.c:4596 · stack telephony-operator/api.py:338

The evidence chain, verified end to end: FreeSWITCH’s core sets start_stamp with format %Y-%m-%d %T (“2026-11-04 18:42:13”, PBX-local time); the stack’s phone API passes it through verbatim; parseStart demands exactly "2006-01-02 15:04" and fails on the trailing seconds — 73/73 records land in Undated. History survives only because its day bucket slices Start[:10], which is why the break stayed invisible until this tab existed. 

// today: rejects every real FreeSWITCH row
const startLayout = "2006-01-02 15:04"   // → "2006-01-02 15:04:05"
Fix Change the layout, fix the const’s comment (a format change must move both consumers — the note stays true), and pin the real format with a fixture in reports_test.go.
Important · trust

F2 — “Unknown” renders as zero, and the caveat is a footnote

internal/web/views/reports.templ (reportsWeek, reportsDays, undated line)

The This-week card reads “— calls 0” — indistinguishable from a silent week, while the totals grid above it says 73. reportsDays renders its heading unconditionally (its siblings reportsBusiestHours and reportsTopContacts guard; it does not), and the one line that explains everything sits at the panel’s very end. A reader’s first conclusion from this page is wrong.

Fix All-undated ⇒ skip week/days/hours and render an EmptyState naming the cause; partial ⇒ keep the sections and move the caveat directly under the temporal block; guard reportsDays; new i18n keys in BOTH maps.
Important · the “who”

F3 — Most-talk-time ranks raw CDR strings

internal/server/reports.go:54 (CRM-only) · panels.go:231 (crmDirectory)

The top contact renders “pifo42h1 · 1 call · 1h45m” — a dialled destination nobody can identify. Name resolution runs through the CRM seam only; the per-extension contacts store — the owner’s own address book — is read by NO display surface (only the Contacts panel itself, panels.go:435). Saved names never reach History, Fax or Reports.

Fix Resolve the top-contact rows through the contacts store first, CRM fallback, at the shared crmDirectory seam so History and Fax inherit the fix; non-dialable remotes render muted mono so garbage is visibly garbage.
Nice to have · the outcome half

F4 — 49 unanswered outgoing calls are invisible

internal/reports/reports.go (Totals) · views reportsTotals

24 answered of 73 outgoing means 49 dials that never connected — the panel’s outcome promise covers only missed inbound. The number is derivable from the totals (Outbound − Answered + Inbound − Missed) but no surface states it.

Fix Named Totals.NoAnswer computed in Aggregate, rendered as a seventh stat card only when > 0 (alert tone, like Missed); check the totals grid’s columns for the extra card.
