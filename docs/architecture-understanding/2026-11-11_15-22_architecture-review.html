03Findings

P1 · High

internal/server crossed the god-package threshold

internal/server — 32 non-test surfaces, 106 files, Ce=25, I=0.93, 342 exported declarations

The 09-30 review flagged the threshold; since then the package absorbed admin, csp_report, islandlatency, livecontext, login_page and passkey_settings — every product surface added since lands here. The methodology bar (>30 exported symbols, >1000 LOC) is exceeded 10× over on exports. The dormant auth-package carve blueprint (docs/modularization/2026-10-17_PROPOSAL.html) covers only the identity quarter.

Fix Execute the three-way carve along already-visible seams: server/auth (login_page, session_api, passkey_*, sso_api, auth_audit — the 2026-10-17 blueprint), server/html (pages, panels, actions, notifier, sse), server/platform (assets, metrics, csp_report, trace, proxy, internal_directory, islandlatency, latency, configjs, export). wiring stays thin in server proper. Mirror of the improved-state D2 rendered this session.
P2 · Medium

View props are typed by infrastructure packages

internal/web/views/{messages,history,voicemail,settings,reports,admin}.templ

templ surfaces consume store.ThreadSummary (7 sites), pbx.CDR (4), pbx.VoicemailSummary/VoicemailMessage (3), plus messaging/textagent/reports prop types — the presentation layer depends on SQL-row and HTTP-client packages for shapes. This is the same edge the 09-30 review flagged; it survived the journal-world swap because the store types stayed the de-facto view models for the surfaces cqrs did not absorb.

Fix Give views their own prop types (or reuse the readmodels *View shapes where they match) and convert once at the server boundary — the same pattern server.crmContacts already uses for CRM people. Removes 5 of views’ 7 non-foundation edges.
P3 · Low

store’s frozen ladder needs its retirement date owned

internal/store/db.go header + docs/planning/2026-11-09_storage-ladder-retirement.md

The ladder is frozen by ruling and everything already answers from system.db; store keeps sessions (by D2 ruling) plus import-only history that retention empties over time. The end state — store as sessions-only — is declared but no row owns verifying when the legacy importers can be deleted.

Fix Add a TODO_LIST row: “delete legacy_* importers when the retention sweep has emptied them on the production deployment” with the detection command (row counts over the legacy tables).
