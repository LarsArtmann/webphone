04Findings

Watch / trigger-based

internal/server sits on the god-package threshold

internal/server — 19 files, 3,268 LOC + 6,073 test LOC, 12/15 sibling imports, 51 touches since 09-23

The methodology flags any package over 1,000 LOC or 20 files for review. server is at 19/3,268 with the strongest touch-rate in the repo. It is not a god module today: the exported surface is 29 doc lines (Deps, New, DisplayVersion), every file serves "the HTTP surface", and its breadth of imports is what a composition surface is for. But three distinct sub-concepts now live inside it — JSON APIs (contacts_api, calls_api, session_api, csrf_api), webhook ingest (webhooks, idempotency), and page/partial rendering (pages, panels, actions) — and the next feature that adds a file crosses the threshold.

Fix Trigger-based carve, not an immediate one: at the next file added to internal/server, split along the three natural seams — server keeps wiring (Deps, chain, mount), server/api takes the JSON endpoints, server/hooks takes webhook ingest + idempotency. Tests move with their files; the two file-name pins (contract_test's three-401-writer allowlist, the DOM contract test) update mechanically. Behavior-safe by construction: the 401 allowlist and toast tests pin outcomes, and the render-diff harness (old-vs-new binary) proves byte parity.
Carried since 09-19 (P2)

fax.Service type-asserts its own gateway seam

internal/fax/service.go:136

s.gateway.(*gateway.Loopback) leaks the implementation through the interface the package exists to hide: adding a second synchronous gateway (a spooler, a second provider) silently takes the wrong branch. The 09-19 review filed this; nothing has changed it since.

Fix Make the receipt carry the fact: Receipt.Sync bool (loopback mints it true; webhook false) or a FaxGateway.ResolvesSynchronously() capability method. The service branches on the contract, not the concrete type. S effort, fax-service tests already cover both arms.
New (cross-file with the data-model review)

Operator config types fail silent instead of fail-closed

internal/config/config.go — Identities map[string]string; domain.SharedContact.Number

Two operator-supplied values still cross the config boundary as raw strings: the identities map keys (meant to be extensions — the doc comment itself warns "keys must be normalized extensions or lookups by the signed-in extension silently miss") and SharedContact.Number (meant to be a Phone — a bad entry renders verbatim in the dial typeahead). Both are validated value-object types in domain today; neither is applied where the data enters the process. A typo produces a silently broken feature, not a failed boot — the opposite of the fail-closed posture everywhere else (timezone typos DO fail the boot, by contrast).

Fix One home: config.Load() validates every identities key via domain.ParseExtension and every shared contact number via domain.ParsePhone, rejecting the boot with the offending key. S–M effort. The data-model review (same date, docs/reviews/) files the type side of this.

05Should this be split into Go modules?

Re-run of the go-modularize assessment (Phase 1 state: single go.mod, 16 packages, monolith) against today's evidence:

SignalWeightToday's reading
Small project, single domainHigh~7.6k non-test LOC, one product surface, one team, one binary
No external Go consumersMediumThe stack consumes the built binary + nixosModules, never packages
All packages change togetherHighPartial — server/views/store dominate, but changes ride single features, not the whole tree
PrototypeHighNo — v2.6.0 in production

Verdict: no go.mod split — same as 09-19, now with more evidence. The composability payoff is zero (nobody imports the packages); the cost is real and specific to this repo: the Nix build hashes a single vendor tree (vendorHash roundtrips already bit this repo once), and the release ritual (release.sh, per-train stack locks, whole-tree tags) would gain per-module version ceremony with no consumer to serve. The DAG the modularize skill enforces via module boundaries is already enforced here by internal/arch at package granularity, green today: domain imports nothing internal, services never import server/web, the island JS graph stays acyclic. A second Go consumer importing internal/domain or internal/gateway is the named revisit trigger.

The refinement that IS worth it operates below module level: the server carve (finding 1) and the seam typing (findings 2–3) deliver everything a module split would, at package-move cost.
