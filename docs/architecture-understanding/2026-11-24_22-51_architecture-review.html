00Summary

212 commits sit between #6 and tonight, but only ten of the 49 that touch Go files are narrative commits; the other 39 are daemon sweeps. The tree moved less than the count suggests: internal/ shed 164 hand-written lines and 366 test lines, the store package lost 702 lines and its last internal import, and the graph gained two edges and no cycle (38 packages, 149 edges, 147 at #6). What did move is governance. Within 30 hours of #6 the depth-pin runway note, the templ depth ratchet and config's named pin landed, and v2.15.0 shipped on 2026-11-21.

Every score holds. Three measurements sharpened the picture. The server hub's depth pin is now exactly full (5,300 of 5,300) and the pin ledger reads four raises and zero lowers in twelve days. The hub's non-html mass is more separable than the carve ruling assumed: its 742-line machine-contract family has zero references into the rest of the hub. And the client side, about 15.9k raw lines (14.8k non-blank), sits outside every size governor the server side now applies.

The bottom line Verdict unchanged: no urgent restructuring. One decision is due before the next hub-touching feature, not after it: the pin's third raise in twelve days. The evidence below names a 742-line seam that leaves the ruled-out html trio untouched, so the choice is now a real one.

P3 · Medium

F8. The readiness-only database rule is already false, and no test would notice

internal/server/server.go (Deps.DB comment) · internal/server/platform/metrics.go

Finding. The Deps.DB comment is explicit: "Readiness probes only (healthz)" and "Nothing else may use"; data access is to ride the services above. platform/metrics.go calls store.CountSessions(r.Context(), p.deps.DB) for the webphone_sessions_stored gauge (landed 2026-11-20), and server.go hands the handle to platform.Deps for that purpose. session.Store has no count method, so the count went around the seam. No test references the rule.

Impact. Small in data terms: one aggregate count, no rows. It is still the first data read through the handle, and it makes platform import store for one metrics line. A prose invariant that is already false teaches readers that the next one is optional too.

Fix: put the count behind the session seam and pin the rule Add Count(ctx) (int64, error) to session.Store (both implementations), read it through platform.Deps.Sessions, delete DB from platform.Deps together with the store import, and add an arch assertion that deps.DB appears in server.go only inside the readiness block. The session store interface changes, so the auth: commit convention and the session-behavior suite apply.

Effort S. Dependencies: none.

P3 · Medium

F9. The journal's boot recipe is transcribed six times and its aggregate list has two homes

internal/app/cqrs.go · internal/cqrs/{threadsregister,contacts,enroll,faxesstore}.go · cmd/webphone/{main,exportlegacy}.go

Finding. The topology literal (system.DeploymentConfig: one sqlite engine, WAL, a source-of-truth instance and a projections instance) appears in six non-test sites: app/cqrs.go for production and the five cqrs.New*System helpers. The aggregate list lives twice: app.NewCqrs composes 11 domain declarations, cqrs.NewCoreSystem composes 10 (Enroll is absent), with no parity test. Two CLI one-shots compose the journal outside the composition root: -enroll-passkey (cqrs.NewEnrollSystem, cqrs.NewEnrollTokens, userauth.New) and export-legacy (cqrs.NewContactsSystem, cqrs.NewContacts), neither carrying the dead-letter decorator production wires.

Impact. Aggregate number 12 is a two-list edit by hand. A topology change is a six-site edit in which five sites are test helpers that can drift from production silently. The AGENTS.md invariant that cmd/webphone receives a fully built app.App holds for the server boot and for neither one-shot.

Fix: one recipe, one list, builders owned by app One cqrs helper owns the topology literal (the five helpers and app.newCqrs call it). One cqrs.FullDomain() (name proposed) is consumed by app.NewCqrs and NewCoreSystem, so parity is by construction. Two app-owned builders (app.EnrollOneShot, app.LegacyContactsCheck, names proposed) let cmd import only app. The one-shots are right to boot a partial system; they should borrow the recipe, not restate it.

Effort S to M. Dependencies: none; cheapest right after a dependency train touches cqrs.
