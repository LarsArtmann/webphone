03Findings

Important

Island invariant drift: the docs forbid an import the code contains

internal/web/assets/island/app/calls.js:11

AGENTS.md states "the island's state.js + auth.js exist so calls/ice/connection never import each other". The graph is acyclic, but calls.js imports getUserAgent from connection.js — a direct edge between two of the three names in the invariant. The boundary holds in spirit (one-way, no cycle) but the letter is already stale, which is exactly how doc-enforced boundaries rot.

Fix Either relocate the accessor into state.js (making the trio truly non-importing) or correct AGENTS.md to describe the real rule — then enforce it (see next finding).
Important

Import direction is enforced by discipline, not by tooling

.buildflow.yml (go-structure-linter skipped via config)

Nothing fails the build if internal/domain grows an import of internal/store tomorrow. The purity that makes this architecture good is currently protected only by AGENTS.md prose — and finding #1 proves prose drifts.

Fix Enable go-structure-linter (documented skip exists, revisit its findings) or add a depguard rule to golangci: internal/domain must import no internal package; internal/store may not import services.
Nice to have

cqrs-lint warnings are indirect-dependency noise

go.mod (indirect go-cqrs-lite/* modules)

cqrs-lint reports "imports go-cqrs-lite but never calls Save/Publish/Dispatch" and a dispatcher version skew. Verified: every go-cqrs-lite module is indirect, pulled in by cqrs-htmx itself; webphone imports only the cqrs-htmx root library (server.go, sse.go) — the deliberate, documented setup-bundle rejection. Not a defect; worth recording as a documented skip so the warnings stop recurring as noise.

Nice to have

Presentation reads PBX DTOs directly

internal/web/views/history.templ, voicemail.templ

The generated views import pbx client types to render history and voicemail. Acceptable today (pbx is a stable in-process client); if the PBX API ever churns, map to thin view models at the server boundary first.

Advisory

nix-checker: vendorHash / hash inlined

flake.nix:48, package/default.nix:17

Extraction-to-file advisory only. Known deviation documented in AGENTS.md (buildflow nix-hash-fix never writes the hash here). No action required beyond awareness.

Strengths

+
Pure domain core internal/domain imports nothing internal; 41 exported symbols across 4 files (26 in ids.go — branded extension/phone/channel IDs — plus message, fax, contact). Everything may depend on it; it depends on nothing.
+
The gateway seam is the architecture's best decision loopback | webhook modes mean the entire server — SSE, webhooks, proxy, panels — runs and is integration-tested with zero PBX present.
+
Fail-closed boundaries /hooks/* return 503 when no secret is configured (tested); every store query is extension-scoped; attachments stream only through session-gated handlers.
+
The DOM contract is a build tripwire TestServedPageHoldsTheDomContract asserts all 35 island element ids on every build — the cross-repo browser E2E contract cannot drift silently.
+
Duplication is near zero jscpd full run: 1 clone, 13 lines, 0.19% — and the clone is a test helper, not product logic.
