P2 · High

Depth-budget pins are nearly full with no pre-sketched next split

internal/arch/depthbudget_test.go · exemption table

Measured this session (raw-line counting, as the test counts): server 5212/5250 (38 lines of headroom), app 1606/1650 (44), server/api 1841/1900 (59), cqrs 5672/6000 (328). The ratchet's designed answer to a red budget is “split the package (the carve precedent)” — but for the server hub the html carve is ruled out (only a real architecture change reopens it), and for app and server/api no next seam is sketched anywhere. The 2026-11-18 line-ownership train already had to ride the server pin (5200→5250, reason in-commit) — the legitimate release valve, but three packages firing inside one feature's growth turns the budget from forcing function into mid-train detour.

Fix: design the splits before they are forced One short design note (no code): (a) app — extract the health/dashboard/adapter glue from app.go (797 LOC) into an app/adapters subpackage, keeping the injector in app proper; (b) server/api — it is already file-per-resource (contacts, transcripts, push, notes, latency…); sketch resource-family subpackages only if it keeps growing; (c) server — no mechanical move is sanctioned; the honest lever is pin-riding commits with reasons, plus the named-reopen trigger. Effort S (sketch) / M (execute when a trigger fires).
P3 · Medium

.templ sources sit outside the depth ratchet

internal/web/views · 16 *.templ files, 3136 LOC

measureDepth counts only non-test, non-generated .go files, so views measures 1205 while its real hand-written mass (3136 templ LOC + i18n.go at 751) is the largest presentation artifact in the repo with no numeric ceiling. Generated *_templ.go is rightly excluded; the .templ sources are hand-written and unmeasured.

Fix: count templ lines as a fourth column Extend measureDepth to also sum *.templ (or add a templ-LOC-only pin for views with a reason). This widens the ratchet's scope — per its own doctrine, do it as a deliberate registry act in one commit. Effort S.
P3 · Medium

Test mass concentrates in one compile unit at the server root

internal/server/*_test.go · 77 files, 15,495 lines

37% of the repo's 41.5k test LOC sits in the single server root package (the 11-11 review counted 74 files / 14.6k — it grew). Every hub-touching train pays the same recompile-and-run cost, and per-package coverage attribution stays blind from this direction (the union-coverage gap is already tracked in ROADMAP; the first manual union run measured 75.8% on 2026-11-15).

Fix: drain opportunistically, never big-bang Tests follow their surfaces: as files carve out (the auth/platform pattern), their tests move in the same commit. No standalone “reorganize tests” train — the motion is free only when it rides a real carve. Effort M amortized.
