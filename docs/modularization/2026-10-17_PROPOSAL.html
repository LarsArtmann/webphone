00Summary

Do not split webphone into multiple go.mod modules. This is the fourth consecutive assessment to reach that verdict, the first three being 2026-09-19, 2026-09-30, and 2026-10-14. This entry re-measures everything the 10-14 report measured, then goes further in three directions that report did not:

1
A scored 7-dimension review Coupling, cohesion, modularity, composability, scalability, service orientation, dependency direction. Overall 4.0 / 5. The one sub-4 dimension is service orientation, and the review shows its fix is the already-triggered internal/server carve, not a go.mod split.
2
A module-readiness audit of the data model The domain core is provably split-ready: 9 branded ids, a closed event union, sentinel errors living with their interfaces, and every seam already speaking consumer-side interfaces. The codebase could split tomorrow. It should not, because readiness was never the missing ingredient. Consumers are.
3
The counterfactual, pre-armed Section 08 contains the full split blueprint (module table, versioning, replace strategy, CI matrix, 6 migration steps with verification and rollback). It is DORMANT. Writing it down does two things: it proves the no-split verdict is a decision rather than an omission, and it converts any future trigger from a two-week research project into a one-day execution.
The bottom line Keep the single module. The 10-14 ratification survives its first real stress test: the heaviest train since the review series began (readmodels + metaengine dogfooding, 105 commits) landed inside the existing package DAG with zero cycles and 3.3% wide commits. The reopen triggers stand unchanged, now with detection commands attached (section 09).

04Fresh evidence, four facts

Decisive · re-verified today

Zero external Go consumers, still

gh search code + local sweep of ~/projects (*.go, vendor excluded) · 0 hits outside this repo

GitHub-wide code search returns only docs and fleet-list mentions (go-health's fleet-repos.txt, the stack's README and lessons). Nothing imports github.com/larsartmann/webphone/... as a module. The composability test every boundary must pass — “does it let consumers import only what they need?” — has no consumers to serve. One consumer exists: the binary, which needs everything.

Structural blocker · FM#6

Every package lives under internal/

all 24 packages, by design

A sub-module's internal/ tree is invisible to every other module. Any split therefore forces one of two strictly worse outcomes: promote packages out of internal/ (publishing app internals as public API against the app's own design) or duplicate shared types across modules (split brain, a declared defect class in this repo). This alone disqualifies the split regardless of every other number in this report.

Benefit already realized

The module DAG already exists at package granularity

internal/arch/arch_test.go · 4 rules, green at assessment time

The graph a split would draw is the graph the packages already form: domain is the zero-internal-dependency core (12 fan-in); ten leaves import nothing internal; services form the mid layer; server and app sit on top. Enforcement is a test suite, not a convention: domain purity, services-never-import-server/web, MustInvoke composition-root-only, island independence. A go.mod boundary would re-deliver this at strictly higher ceremony.

Corroborating · now quantified

The cost side is 172 MB real, not hypothetical

vendor/: 172 MB, 4,262 Go files

The 10-06 and 10-09 red-main incidents came from single dependency bumps tripping the vendorHash. A five-module split means five vendored trees (or a workspace-vendor decision), five bump rituals, whole-tree narHash churn in the two consuming Nix repos per bump, and a GOWORK=off CI matrix. The benefit column is empty (zero consumers); the cost column is the most incident-prone mechanism this repo has.

The go-modularize skill scores four signals before Phase 1. Scored straight, today:

Take the table at its letter: 1 active High + 1 active Medium maps to “proceed with full modularization.” The 10-14 report fudged this arithmetic (it tallied its own table as “1 Medium”). This entry corrects that and makes the stronger argument: the table is a heuristic pre-filter written for repos whose packages CAN become modules. Here the pre-filter's outcome is overruled by three falsifiable structural facts that no signal score reaches:

a
FM#6 makes the split self-defeating With everything under internal/, a split either publishes app internals or duplicates types. There is no configuration of a split that does not violate a declared defect class of this repo.
b
The partial branch is also dead The skill's fallback (“extract only the domain module to establish a clean API surface”) assumes a reader for that surface. A domain module with zero importers is a versioning liability, not an API.
c
The cost mechanism is this repo's most incident-prone Two of the last three red-main incidents were vendor-pinning failures from SINGLE-module bumps. A split multiplies the mechanism by five (section 08 quantifies it).

Migration steps (Phase 5, each independently revertable)

1

domain/go.mod, packages promoted out of internal/

The one unavoidable FM#6 concession: domain alone leaves internal/ because it is the only layer with a plausible external consumer. Verify: go build ./... + arch tests, per module GOWORK=off go build. Rollback: revert one commit.

2

data module (store, readmodels, blob, retention)

Engine DDL + capabilities already self-contained. Verify: readmodels Open-assertions green under GOWORK=off. Rollback: revert one commit.

3

telephony module (gateway, fax, messaging, session, sipcred)

Gateway webhook contract is HTTP, so the consuming bridge is unaffected; version tags land only if the trigger is a Go import. Verify: golden part-header block test. Rollback: revert.

4

integrations module

Nil-safe seams make this mechanical. Verify: buildflow green, smoke boots with seams off AND on. Rollback: revert.

5

Nix + CI re-plumb

goModules hash per module (5 pins), flake buildGraph per module, GOWORK=off CI matrix, stack + pbx-artmann relock. This is the step the cost ledger prices; budget a full day and expect vendorHash friction.

6

Version train (only if proxy-published)

Tag format domain/v1.2.3 et al.; replaces leave go.mod, move version-qualified into go.work; consumer smoke with a scratch module importing domain v1.x.
